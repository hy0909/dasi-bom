# 다시, 봄 (Dasi Bom)

사진 한 장에서 시작해, 가족의 목소리와 AI 질문으로 그날의 기록을 함께 남기는 모바일 프로토타입입니다.

원본 프로토타입: https://dasi-bom-memory-prototype.pongg005.chatgpt.site/
이 저장소는 그 프로토타입을 Vite + React + TypeScript 단일 페이지 앱으로 옮긴 클론입니다.

## 화면 흐름

- **로그인** — 구글 / 카카오로 시작 (목업 인증, 0.7초)
- **가입** — 약관 동의(1/2) → 이름·캐릭터·배경색(2/2)
- **홈** — 내가 참여 중인 앨범(내가 만든 앨범 + 링크로 합류한 앨범). 분류·정렬 드롭다운, 새 앨범 만들기
- **새 앨범 만들기** — 제목만 필수. 시작일·종료일은 비워 두면 사진의 촬영 날짜로 채워집니다. 만들면 바로 초대 화면으로 가고, 거기서 사진 추가로 이어집니다
- **앨범 상세** — `앨범` 탭(사진 → 글 → 목소리 순으로 읽기) / `기록` 탭(사진 · 목소리 · 글 · 연대표). 참여자 이름 줄과 명단 모달
- **사진 추가하기** — 여러 장 선택. 사진의 EXIF에서 촬영 날짜와 위치를 읽어 날짜순으로 정렬하고, 추가하면 바로 기록 시작
- **사진 기록 남기기** — AI 질문 3개에 목소리(실제 마이크 녹음) 또는 글로 답하기
- **사진 기록** — AI가 정리한 글, 문체 선택, 사진 좌우 넘기기
- **초대** — 앨범별 참여 링크 복사 / 공유, 7일 만료와 재발급, 구성원 현황
- **게스트 참여** — 링크로 들어온 비회원이 가입 없이 사진마다 글로 기록
- **알림 · 내 설정** — 알림 2건(고정), 프로필 수정, 로그아웃, 회원 탈퇴

서버는 없습니다. 데이터는 프론트 메모리에 있고, 새로고침하면 로그인 세션만 남습니다. 자세한 건 `docs/`의 문서 세 개를 보면 됩니다.

- [기능명세서](docs/기능명세서.md) — 기능 단위 표. 화면 옆에 두고 보는 용도
- [개발현황](docs/개발현황.md) — FE / BE 진행 상태와 서버 연동 지점
- [UX-FLOW](docs/UX-FLOW.md) — 화면 ID, 분기, 예외 경로. [docs/ux-flow/](docs/ux-flow/)에 플로우 JSON과 PNG 9장이 있습니다

## 인증

구글 / 카카오 소셜 로그인을 **프로토타입 목업**으로 구현했습니다. 실제 OAuth 대신
`localStorage`(`dasiBomAuth`, `dasiBomAccounts`)에 세션과 가입 이력을 저장합니다.

- 신규 계정 → 약관 동의 → 프로필 설정 → 홈
- 기존 계정 → 바로 홈 / 가입을 중간에 멈췄으면 약관 단계부터 재개
- 초대 링크(`?invite=SUMMER`)로 들어오면 가입을 마친 회원은 그 앨범에 합류해 상세로, 비회원은 게스트 플로우로 갑니다. 만료된 링크(`?invite=JEJU`)는 둘 다 막힙니다
- 로그아웃은 세션만, 회원 탈퇴(두 번 누르기)는 가입 이력까지 지웁니다

실제 연동이 필요해지면 `src/lib/auth.ts` 의 `mockAuthorize()` 한 곳만 Google Identity Services /
Kakao SDK 호출로 교체하면 됩니다.

## 실행

```bash
npm install
npm run dev
```

포트는 터미널에 뜨는 값을 씁니다(기본 5173, `PORT=5174 npm run dev` 처럼 지정 가능). 초대 링크는 주소 뒤에 `?invite=SUMMER` 를 붙여 확인합니다.

빌드는 `npm run build`, 결과물은 `dist/` 에 생성됩니다.

## 배포

`main` 브랜치에 푸시하면 GitHub Actions가 GitHub Pages로 자동 배포합니다.

## 기술

- Vite 7, React 19, TypeScript
- Tailwind CSS v4 + shadcn/ui (Radix 기반). UI 프리미티브는 `src/components/ui/`
- 디자인 토큰은 `src/index.css` 한 곳에서 관리 (Zapier 계열 웜 크림 / 커피 잉크 / 오렌지 CTA)
- 시드 사진은 Unsplash 이미지입니다. 올린 사진은 브라우저 안(blob URL)에만 있어 새로고침하면 사라집니다
- 촬영 정보는 브라우저에서 직접 읽습니다. EXIF 파서는 `src/lib/exif.ts`(외부 라이브러리 없음, JPEG·PNG·HEIC), 좌표 → 지명은 `src/lib/geocode.ts`

## 촬영 날짜 · 장소

사진을 추가하면 파일 안의 EXIF에서 촬영 시각과 GPS 좌표를 읽어, 앨범 상세의 날짜·장소·연대표에 그대로 씁니다.
EXIF가 없는 사진만 파일 수정 시각과 "위치 없음"으로 갑니다. 앨범의 시작일·종료일을 비워 두면
가장 이른 촬영 날짜와 가장 늦은 촬영 날짜가 앨범 기간이 되고, 사진이 늘면 기간도 따라 넓어집니다.
직접 고른 날짜는 그대로 유지되고, 앨범 정보 화면의 [사진 날짜로 되돌리기]로 다시 사진 날짜를 따르게 할 수 있습니다.

좌표를 지명으로 바꾸는 일은 **무료로만** 처리합니다. 이용자가 늘어도 요금이 생기지 않는 구조입니다.

1. OpenStreetMap의 공개 지명 검색(Nominatim) — API 키도 계정도 요금제도 없습니다. 공용 서버라 요청은 1초에 한 번으로 늦추고, 같은 자리(약 1km)는 캐시해 다시 묻지 않습니다
2. 실패하거나(오프라인·혼잡·차단) 5초 안에 답이 없으면 `src/lib/geocode.ts`의 내장 좌표표로 가까운 지명을 고릅니다 — 네트워크가 없어도 되고 언제까지나 공짜입니다
3. 표에도 없는 먼 곳이면 좌표를 그대로 보여줍니다. 지명을 지어내지 않습니다

## 디자인 시스템 요약

| 토큰 | 값 | 쓰임 |
|---|---|---|
| `--canvas` | `#fffefb` | 페이지 바탕 (순백 아님) |
| `--canvas-soft` | `#f8f4f0` | 카드 표면 |
| `--ink` | `#201515` | 헤드라인·본문 잉크 |
| `--primary` | `#ff4f00` | 유일한 강조색, 주요 CTA |
