## 서버 없이도 FE에서 먼저 손봐야 할 것

서버가 붙어도 저절로 풀리지 않는 프론트 몫입니다. 연동 전에 정리해 두는 게 낫습니다.

| 무엇 | 지금 | 왜 문제 | 어디 |
| --- | --- | --- | --- |
| 선택한 사진 전달 | 앱 상태에 앨범 id만 있고 사진 id가 없다 | 어느 사진을 눌러도 기록 화면은 첫 '기록 중' 사진, 글 화면은 첫 사진을 연다 | `App.tsx` 상태, `interview.tsx:34`, `voice.tsx:23`, `story.tsx:33` |
| 사진 식별자 | 사진에 id가 없고 `title`을 key로 쓴다 | 같은 파일명을 두 번 올리면 key 충돌 | `data/photos.ts` |
| 사진 상태 변경 | `기록 완료`로 바꾸는 함수가 없다 | 기록을 끝내도 상태가 안 바뀐다 | `data/photos.ts` |
| 글 편집 입력 | `defaultValue` 비제어 | 저장 시 값을 잡을 수 없다 | `story.tsx:88-92, 118` |
| 목소리 재생 UI | 아이콘 토글 + 토스트 | 오디오 URL이 와도 재생 코드가 없다 | `detail.tsx:383`, `story.tsx:144` |
| 앨범 삭제 확인 창 | 없음 | | `home.tsx:206` |
| 알림 → 앨범 연결 | 항상 마지막으로 연 앨범 | | `notices.tsx` |
| 게스트 완료 통계 | "3장 / 2개" 고정 | | `guest.tsx:288-299` |
| 업로드 blob URL | revoke 안 함 | 메모리 누수 | `photos.ts:254` |
| 초대 코드 생성 | `create.tsx`가 `newInviteCode()`를 안 쓰고 같은 로직을 다시 쓴다 | 중복 | `create.tsx:50` |

## 지금 가짜로 돌아가는 것

데모에서는 잘 돌아가지만 실제로는 아무것도 저장되지 않는 부분입니다.

| 무엇 | 지금 | 실제로 필요한 것 |
| --- | --- | --- |
| 로그인 | localStorage 세션 | 구글·카카오 OAuth |
| 앨범·구성원·사진·글 | 시드 상수 + 메모리 | DB, 조회·저장 API |
| 사진 업로드 | 메모리 반영, blob URL, 촬영 시각은 파일 수정 시각 | 스토리지 업로드, EXIF 촬영 시각·위치 |
| 목소리 | 녹음 후 폐기 | 오디오 업로드, 재생 URL |
| AI 질문·글 | 고정 문구 | 사진 기반 질문, 기록 요약, 문체 재생성 |
| 초대 만료 | 브라우저 시각 | 서버 시각 검증 |
| 알림 | 고정 2건 | 이벤트 생성, 읽음 처리 |
| 게스트 답 | 사라진다 | 저장 |

## 서버 연동 지점 (FE 파일 기준)

지금 로컬에서 처리하는 자리가 곧 API 호출로 바뀌어야 하는 자리입니다.

| 기능 | 지금 자리 | 바뀌어야 할 것 |
| --- | --- | --- |
| 로그인 | `lib/auth.ts` `mockAuthorize()` | OAuth 토큰 교환 → 계정 |
| 가입·프로필 | `lib/auth.ts` `completeSignup`, `updateProfile` | 프로필 생성·수정 |
| 앨범 목록 | `App.tsx` `useState(initialAlbums)` + `data/membership.ts` | 참여 앨범 목록(역할 포함) |
| 앨범 생성 | `App.tsx` `onCreate` | 생성 → id·초대 코드 응답 |
| 앨범 수정 | `App.tsx` `onSave` | 수정 |
| 사진 추가 | `upload.tsx` `addPhotos()`, `photos.ts` `photoFromFile()` | 업로드 → 사진 레코드. blob URL을 서버 URL로 |
| 질문·답 | `interview.tsx` `questions` 상수, `submit()` | 질문 조회, 답 저장 |
| 목소리 | `voice.tsx` [이 목소리 남기기] onClick | 오디오 업로드 |
| 글 | `story.tsx` [기록 저장하기] onClick, 문체 버튼 | 글 저장·재생성 |
| 초대 | `invite.tsx` 링크 조립, `App.tsx` `reissueInvite` | 링크 조회·재발급 |
| 링크 합류 | `App.tsx` 부팅 effect (`joinAlbum`, `joinMyAlbum`) | 합류 |
| 게스트 | `guest.tsx` 제출 핸들러 | 게스트 등록·답 저장 |
| 알림 | `notices.tsx`, `bottom-nav.tsx`의 `count` | 목록·읽음 |

## 서버 붙이는 순서 제안

앞 단계가 되면 뒤 단계가 자연스럽게 풀립니다.

| 순서 | 묶음 | 왜 먼저인가 |
| --- | --- | --- |
| 1 | 로그인, 내 정보 | 사용자가 있어야 앨범 주인이 정해진다 |
| 2 | 앨범 CRUD, 내 앨범 목록(역할 포함) | 화면 대부분이 이 데이터를 본다. 분류 필터·삭제 메뉴도 역할에 걸려 있다 |
| 3 | 사진 업로드, 사진 목록, EXIF | 기록·목소리·연대표가 전부 사진에 붙는다 |
| 4 | 초대 링크 발급·합류 | 구성원이 생겨야 협업 흐름이 돈다 |
| 5 | 기록 저장, 목소리 업로드, 사진 상태 변경 | 사진과 구성원이 있어야 의미가 생긴다 |
| 6 | AI 질문·글 생성 | 기록이 쌓인 뒤에 붙이면 된다 |
| 7 | 알림 | 나머지가 다 돌아간 뒤 마지막 |
