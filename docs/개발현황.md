# 개발 현황

기능 하나하나가 지금 어디까지 돼 있는지 정리한 표입니다. 기능 ID는 [기능명세서](./기능명세서.md)와 같습니다.
기준 코드 `dd8647e` (2026-09-18). 배포본과 같은 빌드입니다.

한 줄 요약: 백엔드 동작이 일부 확정됐고, 프론트는 아직 그 서버를 한 번도 부르지 않습니다. 화면은 다 있지만 데이터는 여전히 프론트 메모리에 있어서 새로고침하면 로그인과 게스트 닉네임 빼고 전부 초기화됩니다. 게다가 확정된 내용과 화면이 이미 어긋난 곳이 있습니다 — 초대 링크 형식, 질문 개수, 사진 상태 판정.

| 표기 | 뜻 |
| --- | --- |
| O | 끝남 |
| △ | 일부만 / 진행 중 |
| X | 안 함 |
| ? | 확인 필요 — 모른다는 뜻이다. '안 했다'(X)와 다르다 |
| - | 필요 없음 |

칸 뜻 — **FE**: 화면과 동작 / **BE API**: 서버 쪽 구현 / **연동**: 프론트를 서버에 붙이는 작업 / **상태**: 셋을 합친 판단.

**BE API 칸**은 아래 확정된 동작이 닿는 기능만 O입니다. 나머지는 모르니 `?`로 둡니다. 엔드포인트 이름과 스키마는 아직 받은 게 없어 이 문서에 적지 않습니다 — 지어내지 않습니다.
**연동 칸은 전부 X입니다.** 프론트가 우리 서버를 부르는 자리는 아직 한 곳도 없습니다. 앱 전체에서 바깥으로 나가는 요청은 지명 검색(Nominatim) 하나뿐입니다(`src/lib/geocode.ts:65`).

## 확정된 백엔드 동작

이 다섯 가지는 정해진 것으로 보고 씁니다.

1. 답변, 음성 파일, STT, AI facts, story를 모두 DB/Storage에 저장한다.
2. 질문은 사진을 올릴 때 기본 질문이 만들어지고, AI가 질문을 바꿀 수 있으며 꼬리질문도 붙는다.
3. 모든 질문에 답하지 않아도, 제출된 답변이 분석되면 story를 만들 수 있다.
4. 게스트는 DB에 참여자로 저장되고 HttpOnly 세션을 쓴다. 음성으로도 답할 수 있다.
5. 초대 링크는 `/invite/<긴 랜덤 토큰>`이고 7일 동안 유효하다.

## 서버 붙이는 순서 제안

앞 단계가 되면 뒤 단계가 자연스럽게 풀립니다.

| 순서 | 묶음 | 왜 먼저인가 |
| --- | --- | --- |
| 1 | 로그인, 내 정보 | 사용자가 있어야 앨범 주인이 정해진다 |
| 2 | 앨범 CRUD, 내 앨범 목록(역할 포함), 표지 값 | 화면 대부분이 이 데이터를 본다. 분류 필터·삭제 메뉴도 역할에 걸려 있다 |
| 3 | 사진 업로드, 사진 목록 | 기록·목소리·연대표가 전부 사진에 붙는다. 업로드가 곧 질문 생성이라(2) 질문보다 먼저다 |
| 4 | 초대 링크 발급·합류, 게스트 세션 | 구성원이 생겨야 협업 흐름이 돈다. 프론트는 링크 경로부터 바꿔야 한다 |
| 5 | 질문 조회, 답 저장, 음성 업로드 | 사진과 구성원이 있어야 의미가 생긴다 |
| 6 | story 생성·조회 | 답이 쌓인 뒤에 붙이면 된다 |
| 7 | 알림 | 나머지가 다 돌아간 뒤 마지막 |
