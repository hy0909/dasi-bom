# 다시, 봄 — 기능 명세

프로토타입에 실제로 들어 있는 화면과 동작만 적었습니다. 화면을 옆에 띄워 놓고 표를 따라가면 됩니다.

"서버 몫" 칸은 **확정**과 **미정**으로 나눠 적었습니다. 확정은 백엔드에서 이미 정해진 동작이고, 미정은 아직 아무것도 정해지지 않은 자리입니다. API 경로와 요청·응답 모양은 어디에도 적지 않았습니다 — 정해진 것이 없습니다.

지금까지 확정된 백엔드 동작은 다섯 가지입니다.

1. 답변, 음성 파일, STT, AI facts, story 를 모두 DB·Storage 에 저장한다.
2. 질문은 사진을 올릴 때 기본 질문이 만들어지고, 그 뒤 AI 가 질문을 바꾸거나 꼬리질문을 더할 수 있다.
3. 모든 질문에 답하지 않아도, 제출된 답변이 분석되면 story 를 만들 수 있다.
4. 게스트도 DB 에 참여자로 저장되고 HttpOnly 세션을 쓴다. 음성으로도 답할 수 있다.
5. 초대 링크는 `/invite/<긴 랜덤 토큰>` 이고 발급일부터 7일 동안 쓴다.

이 다섯 가지와 지금 프로토타입이 어긋나는 자리는 아래 '프론트와 백엔드가 어긋나는 곳'에 모아 두었습니다.

기준 코드 `dd8647e` (2026-09-18). 배포본 https://hy0909.github.io/dasi-bom/ 도 같은 커밋입니다.

- 실행: `npm run dev` → 터미널에 뜨는 주소 (기본 5173, `PORT=` 로 바꿀 수 있음)
- 초대 링크 테스트: 주소 뒤에 `?invite=SUMMER` (유효) / `?invite=JEJU` (만료) / `?invite=SEA` (아직 내 앨범이 아닌 앨범)

## 용어

| 용어 | 뜻 |
| --- | --- |
| 앨범 | 여행이나 시기 하나. 사진·목소리·글이 여기에 묶인다 |
| 구성원 | 앨범에 참여 중인 사람. 만든 사람(owner)과 링크로 들어온 사람(member)을 구분한다. 이 구분이 쓰이는 곳은 홈의 분류 필터, 삭제 메뉴 노출, 상세 명단 모달의 내 줄 문구 세 곳 |
| 기록 | 가족이 사진에 남기는 목소리·글, 그리고 AI가 그걸 모아 정리한 글. 화면에서는 '답변'이라는 말을 쓰지 않는다 |
| 기록 상태 | 사진 한 장 단위. `기록 전` / `기록 완료` 둘뿐. 앨범 자체에는 상태가 없다 |
| 초대 링크 | 앨범마다 코드 하나. 발급일부터 7일 |
| 게스트 | 가입 없이 링크로 들어와 기록을 남기는 사람. 지금 화면에서는 글로만 남길 수 있다 |

## 기록 (사진·목소리·글)

| ID | 기능 | 화면 | 사용자가 하는 일 | 규칙 · 지금 동작 | 서버 몫 |
| --- | --- | --- | --- | --- | --- |
| C-01 | 사진 추가 | 사진 추가하기 | 여러 장 고르고 빼기 → [사진 n장 추가하고 기록 시작] | 데스크톱 크로미움은 폴더 선택창(File System Access, 다운로드 폴더부터), 그 외는 파일 input. 이미지 타입이면 전부 통과(안내 문구는 JPG·PNG·WebP). 한 앨범은 20장까지 — 넘게 고르면 남은 자리만큼만 받고 몇 장만 받았는지 알린다. 이 상한이 실제로 걸리는 곳은 이 화면 하나뿐이다. 촬영 시각과 위치는 사진의 EXIF에서 읽고(시각이 없으면 파일 수정 시각, 위치가 없으면 "위치 없음"), GPS 좌표는 지명으로 바꿔 "제주 애월"처럼 적는다. 고른 순서와 무관하게 촬영순 정렬. 미리보기마다 읽어 온 날짜·장소를 보여주고, 기간을 비워 둔 앨범이면 어떤 기간으로 채워지는지도 알려준다. 완료하면 앨범에 실제로 들어가고(메모리) 곧바로 기록 화면으로 넘어간다. 새로고침하면 사라진다 | 확정: 사진을 올리면 그 사진의 기본 질문이 만들어진다. 미정: 업로드, 20장 상한이 서버 규칙인지, EXIF 값을 누가 읽는지 |
| C-02 | 기록할 사진 목록 | 상세 상단 [기록] | 남은 사진 훑고 하나 선택 | 제목은 "기록할 사진". `기록 전` 필터로 열리고 칩으로 전체·기록 완료를 오갈 수 있다. "n장 중 m장 남았어요", 다 끝났으면 "모든 사진의 기록이 끝났어요". 줄마다 번호·날짜·장소와, 들어온 목소리·글 표시. 어떤 걸 눌러도 기록 화면은 저장된 `photo.status` 가 `기록 전`인 첫 사진을 연다 — 선택값이 넘어가지 않는다 | 확정: 답변과 story 가 DB 에 있으니 남은 사진 판정도 서버 데이터에서 나온다. 미정: 조회 방법 |
| C-03 | AI 질문에 답하기 | 사진 기록 남기기 | 질문 3개에 목소리 또는 글로 답, 건너뛰기 | 질문은 고정 문구 3개(`interview.tsx:14-18`, 사진과 무관). 진행 바 "질문 n / 3". 2·3번째 질문에 붙는 '이전 기록' 인용도 고정 문구. 글은 500자, 비면 제출 불가. 답은 저장되지 않고 사진 상태도 바뀌지 않는다. 3번째 답을 내야 글 화면으로 가고, 건너뛰기는 다음 질문, 마지막에서는 상세로 빠진다 | 확정: 기본 질문은 업로드 때 만들어지고 AI 가 바꾸거나 꼬리질문을 더할 수 있다. 답변은 DB 에 저장되고, 모든 질문에 답하지 않아도 제출된 답변이 분석되면 story 가 만들어진다. 미정: 질문이 몇 개까지 늘어나는지, 꼬리질문이 붙는 시점, 건너뛴 질문의 처리 |
| C-04 | 목소리 녹음 | 목소리로 답하기 | 녹음·정지·다시 녹음·들어보기·남기기 | MediaRecorder로 진짜 녹음된다. 권한 거부면 토스트. "최대 5분" 문구만 있고 자동 정지는 없다. 미리듣기는 진짜 재생. [이 목소리 남기기]는 토스트를 띄우고 글 화면으로 갈 뿐, 녹음 파일은 버려진다. 질문 문구는 1번 질문으로 고정 | 확정: 음성 파일과 STT 결과가 Storage·DB 에 저장된다. 미정: 업로드 방식, 길이 제한이 서버 규칙인지 |

| 구성원 수 | 앨범 상세의 명단 모달은 나를 더해 센다("기록 중인 사람 n명" = 나 + 참여자). 초대 화면은 같은 제목을 쓰면서 참여자만 센다. 명단에 내 이름이 없는 시드 앨범에서는 두 화면의 숫자가 1 차이 난다 |
| school1 사진 수 | 시드 앨범 school1 은 사진이 20장(`FIRST_GRADE_TITLES`)인데, `albums.ts:64`·`albums.ts:71`·`membership.ts:20`·`photos.ts:210`의 주석과 앨범 설명은 아직 "50장"이라고 말한다. 화면에 보이는 설명 문구도 "사진 50장으로 모았어요"다 |

## 앱이 켜질 때

```
주소에 ?invite=코드 가 있고, 시드 앨범(EU23 · JEJU · SUMMER · SEA · SCH1) 코드인가?
├ 예 → 발급 후 7일이 지났나?
│      ├ 예 → 만료 안내 (회원·비회원 공통)
│      └ 아니오 → 가입을 마친 세션이 있나?
│             ├ 예 → 앨범에 합류 → 주소에서 코드 제거 → 앨범 상세
│             └ 아니오 → 게스트 랜딩
└ 아니오 (코드 없음 / 모르는 코드) → 세션이 있나?
       ├ 없음 → 로그인
       ├ 있음, 가입 완료 → 홈
       └ 있음, 가입 중단 → 약관(1/2)부터 다시
```

## 화면 이동

| 출발 | 도착 | 조건 |
| --- | --- | --- |
| 로그인 | 약관 → 프로필 → 홈 | 신규 계정 |
| 로그인 | 홈 | 가입을 마친 계정 |
| 로그인 | 게스트 랜딩 | [초대 링크로 참여하기] — 앨범은 마지막으로 연 앨범(처음 켰을 땐 시드 첫 앨범) |
| 홈 | 앨범 상세 | 카드 (열림 모션) |
| 홈 `···` | 앨범 정보 / 초대 | 정보 수정 / 공유 |
| 홈 | 새 앨범 만들기 | 상단 카드 또는 오른쪽 아래 + |
| 새 앨범 만들기 | 초대 (생성 직후) | 자동 (0.5초) |
| 초대 (생성 직후) | 사진 추가 | [앨범에 사진 추가] |
| 초대 (생성 직후) | 홈 | 오른쪽 위 ✕ (닫기) |
| 앨범 상세 | 기록할 사진 | 상단 [기록] |
| 앨범 상세 | 사진 추가 | 상단 [사진 추가] |
| 앨범 상세 | 초대 / 앨범 정보 | 케밥 → 구성원 초대 / 앨범 수정 |
| 앨범 상세 (앨범 탭) | 사진 크게 보기 | 사진 누름 |
| 앨범 상세 (앨범 탭) | 사진 기록 남기기 | 글 없는 사진의 [기록하기] |
| 기록 탭 · 기록할 사진 · 연대표 | 사진 기록 남기기 | 기록 전 사진 |
| 기록 탭 · 기록할 사진 · 연대표 | 사진 기록 (글) | 기록 완료 사진 |
| 기록 탭 (목소리) | 목소리로 답하기 | 줄 오른쪽 연필 |
| 사진 추가 | 사진 기록 남기기 | 추가 완료 시 자동 |
| 사진 기록 남기기 | 목소리로 답하기 | [목소리로 답하기] |
| 목소리 / 3번째 답 | 사진 기록 (글) | [이 목소리 남기기] / [기록 완성하기] |
| 게스트 랜딩 | 참여자 정보 → 기록 남기기 → 완료 | [이 앨범에 참여하기] |
| 초대 링크 | 상세 / 게스트 / 만료 안내 | 위 분기 |

뒤로가기는 두 가지입니다. 앨범 정보·기록할 사진·프로필 수정·초대(상세에서 들어온 경우)는 실제로 거쳐온 화면으로 돌아가고, 나머지는 목적지가 고정입니다(상세→홈, 기록·글→상세, 목소리→기록, 사진 추가→상세, 참여자 정보→게스트 랜딩, 기록 남기기→참여자 정보). 하단 탭 4개(앨범·초대·알림·나) 사이를 오갈 때는 기록을 쌓지 않습니다. 홈 `···`→공유도 탭 사이 이동이라, 그렇게 연 초대 화면에는 뒤로가기가 없고 하단 탭이 그대로 보입니다.

## 데이터가 어디에 있나

| 데이터 | 지금 | 새로고침하면 |
| --- | --- | --- |

| 앨범 목록 · 초대 코드 | React state (시드 5개에서 시작) | 시드로 돌아간다 |
| 내가 참여 중인 앨범(역할) | 메모리 스토어 | 시드로 |
| 구성원 | 메모리 스토어 | 시드로 |

| 답 · 녹음 파일 · 글 수정 | 아무 데도 저장되지 않는다 | - |
| 알림 | JSX에 고정 | - |

시드 앨범은 다섯입니다. 유럽여행(EU23)·할머니와 보낸 여름(SUMMER)·첫째 초등학교 1학년(SCH1)은 내가 만든 앨범, 제주(JEJU)는 초대받은 앨범, 바닷가(SEA)는 링크를 타야 들어옵니다. 제주 링크는 발급 23일 전으로 잡혀 있어 처음부터 만료 상태이고, 바닷가 링크는 6일 전이라 오늘이 마지막 날입니다.
