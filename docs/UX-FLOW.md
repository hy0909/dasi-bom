# 다시, 봄 — UX 플로우 기획서

UX 플로우 다이어그램(FigJam)을 그리기 위한 입력 문서입니다. 화면 ID는 노드로, 분기 조건(Y/N)·역할·상태·예외 경로는 엣지로 그대로 옮길 수 있게 정리했습니다. 용어와 기능 ID(A-01~E-03)는 [기능명세서](./기능명세서.md)와 같습니다.

기준 코드 `4253da4` (2026-09-16). 실행은 `npm run dev`. 초대 링크는 주소 뒤에 `?invite=SUMMER`(유효) / `?invite=JEJU`(만료) / `?invite=SEA`(아직 내 앨범이 아닌 앨범)를 붙여 확인합니다.

## 1. 역할

| 역할 | 누구인가 | 인증 | 하는 일 |
|---|---|---|---|
| `HOST` | 가입을 마친 회원 | 구글 / 카카오 목업 로그인(0.7초) + 약관·프로필 가입 | 앨범 만들기·정보 수정, 사진 추가, 기록, 초대, 링크로 다른 앨범에 합류 |
| `GUEST` | 초대 링크로 들어온 비회원 | 없음. 닉네임만 `localStorage.dasiBomGuest`에 저장 | 사진마다 글로 기록. 목소리 없음 |

회원은 앨범마다 만든 사람(`owner`)과 링크로 들어온 사람(`member`)으로 나뉩니다. 이 구분이 쓰이는 곳은 홈의 분류 필터, 홈 카드의 삭제 메뉴, 상세 명단 모달의 내 줄 문구 세 곳입니다.

## 2. 용어

| 용어 | 뜻 |
|---|---|
| 앨범 | 여행이나 시기 하나. 사진·목소리·글이 여기에 묶인다. 앨범 자체에는 상태가 없다 |
| 구성원 | 앨범에 참여 중인 사람. 만든 사람(owner)과 링크로 들어온 사람(member)을 구분한다. 화면 문구는 '기록 중인 사람' |
| 기록 | 가족이 사진에 남기는 목소리·글, 그리고 AI가 그걸 모아 정리한 글. 화면에서는 '답변'이라는 말을 쓰지 않는다 |
| 기록 상태 | 사진 한 장 단위. `기록 중` / `기록 완료` 둘뿐 |
| 초대 링크 | 앨범마다 코드 하나. `주소?invite=코드`. 발급일부터 7일. 화면 문구는 '참여 링크' |
| 게스트 | 가입 없이 링크로 들어와 글로만 기록을 남기는 사람 |
| 내 앨범 | 홈에 보이는 목록. 내가 만든 앨범과 링크로 합류한 앨범만 |

표기 규칙 (`src/data/photos.ts`, `src/data/album.ts`):

| 자리 | 형식 | 예 |
|---|---|---|
| 사진 날짜 · 시간 | 촬영 시각(`takenAt`)에서 만든다 | `2023년 7월 11일`, `오후 7시 40분` |
| 사진 위 캡션 | 날짜 · 시간 · 장소 | `2023년 7월 11일 · 오후 7시 40분 · 파리` |
| 앨범 기간 | 같은 해면 뒤쪽 연도 생략 | `2023년 7월 10일 - 7월 17일` |
| 홈 카드 · 앨범 선택기 | 시작일만 | `2023년 7월 10일` |
| 연대표 · 사진 타일 | 짧은 날짜 | `7. 11` |
| 목소리 길이 | 분:초 | `0:37` |

## 3. 전역 상태

| 상태 | 값 | 어디에 | 비고 |
|---|---|---|---|
| `screen` | 화면 키 20개 중 하나 | React state (`src/App.tsx`) | 첫 값은 `login` |
| `history` | 거쳐온 화면 스택 | React state | 뒤로가기(`goBack`)가 꺼내 쓴다. 탭↔탭 이동 때 비운다 |
| `albums` | 앨범 목록. 시드 4개에서 시작 | React state | 만들기·정보 수정·링크 재발급이 여기를 고친다 |
| `openId` | 지금 열어 둔 앨범 id | React state | 상세·앨범 정보·기록할 사진·기록·목소리·글·사진 추가·알림 클릭·초대 기본 선택이 모두 이 앨범을 본다. 첫 값은 첫 시드 앨범 |
| `justCreated` | 앨범을 막 만든 직후인가 | React state | 초대 화면을 '앨범을 만들었어요' 모드로 바꾼다. 초대 화면을 벗어나면 false |
| `invitedId` | 링크로 들어온 앨범 id | React state | 게스트 화면이 이 앨범의 커버·제목·사진을 본다. 없으면 `openId` 앨범 |
| `inviteExpired` | 링크가 만료됐는가 | React state | true면 게스트 랜딩이 만료 안내로 바뀐다 |
| `ready` | 부팅이 끝났는가 | React state | false 동안 부팅 화면 |
| `dasiBomAuth` | 현재 세션 `Account` — provider · email · name · tone(캐릭터 0~3) · color(배경색 0~7) · marketing · onboarded · createdAt | `localStorage` | 로그아웃·탈퇴 때 삭제 |
| `dasiBomAccounts` | 가입 이력. 공급자별 계정 1개 | `localStorage` | 재로그인 때 신규/기존 판단. 탈퇴 때만 지워진다 |
| `dasiBomGuest` | 게스트 닉네임 | `localStorage` | 로그아웃·탈퇴 때 함께 삭제 |
| `?invite=<코드>` | 초대 코드 | URL 쿼리 | 첫 로드에 한 번만 읽는다. 아는 코드는 시드 4개(EU23 · JEJU · SUMMER · SEA) |
| 사진 스토어 | 앨범 id → 사진 목록(`status` · `takenAt` · `voices` · `story`) | 메모리 (`src/data/photos.ts`) | 사진 추가로만 늘어난다 |
| 구성원 스토어 | 앨범 id → 구성원 목록(이름 · 캐릭터 · 색 · 상태) | 메모리 (`src/data/family.ts`) | 회원의 링크 합류로만 늘어난다 |
| 멤버십 스토어 | 앨범 id → 내 역할(owner / member) | 메모리 (`src/data/membership.ts`) | 홈 목록·분류 필터·삭제 메뉴의 근거 |

`albums`와 메모리 스토어 3개는 새로고침하면 시드로 돌아갑니다. 남는 것은 localStorage 3키뿐입니다.

시드 앨범은 넷입니다. 2023년 유럽여행(EU23, 내가 만듦, 발급 2일 전) · 할머니와 보낸 여름(SUMMER, 내가 만듦, 1일 전) · 제주 가족여행(JEJU, 초대받음, 23일 전 → 이미 만료) · 바닷가 산책(SEA, 아직 내 앨범 아님, 6일 전 → 오늘이 마지막 날).

## 5. 이동 규칙

뒤로가기는 두 종류입니다.

| 종류 | 화면 | 어디로 |
|---|---|---|
| 방문 기록(`history`)에서 꺼낸다 | `S3E_ALBUM_EDIT`, `S3L_RECORD_LIST`, `S10E_PROFILE_EDIT`, `S7_INVITE`(앨범 상세에서 들어온 경우만) | 실제로 거쳐온 화면. 기록이 비어 있으면 홈 |
| 목적지 고정 | `S2_CREATE`→홈, `S3_DETAIL`→홈, `S4_INTERVIEW`→상세, `S5_VOICE`→기록 남기기, `S6_STORY`→상세, `S8_UPLOAD`→상세, `G2_INFO`→랜딩, `G3_ANSWER`→참여자 정보, `A3_PROFILE`→약관, `A2_TERMS`→로그인(세션 삭제) | 들어온 길과 무관 |

- 탭 홈 4개에는 뒤로가기가 없다. 홈만 상단 바(워드마크 → 홈, 아바타 → 내 설정)가 있고, 나머지 셋은 상단 바 없이 제목이 홈 워드마크와 같은 높이에서 시작한다.
- 탭 홈 사이를 오가면 `history`를 비운다. 홈 `···`→공유도 홈→초대 이동이라 기록이 비고, 초대 화면에 뒤로가기가 붙지 않는다.
- 탭 홈이 아닌 화면으로 가면 지금 화면을 `history`에 쌓는다. 지금 화면과 같은 화면으로는 가지 않는다.
- 앨범 만들기가 끝나면 `history`를 `[home]`으로 갈아끼우고 초대로 간다. 만들기 화면으로는 돌아갈 수 없다.
- 새 앨범 만들기 입구는 홈의 카드와 우측 하단 원형 ＋ 둘이다. 하단 탭에는 없다.

## 6. 진입 분기

```
앱 로드 → S0_BOOT (ready=false)
  └ 주소의 ?invite= 코드가 시드 앨범 코드(EU23 · JEJU · SUMMER · SEA)인가?
      ├ Y → invitedId = openId = 그 앨범
      │    └ 링크가 만료됐는가? (발급 시각 + 7일 ≤ 브라우저 현재 시각)
      │        ├ Y → inviteExpired=true → G1_WELCOME (만료 안내. 회원·비회원 모두 참여 불가)
      │        └ N → 가입을 마친 세션(onboarded)이 있는가?
      │              ├ Y → 구성원 스토어에 나를 추가 (같은 이름이 있으면 무시)
      │              │     → 멤버십 스토어에 member로 추가 (이미 내 앨범이면 그대로)
      │              │     → 주소에서 ?invite= 제거 → S3_DETAIL
      │              └ N → G1_WELCOME (게스트 흐름. 가입을 중단한 세션도 여기)
      └ N (코드 없음 / 모르는 코드 — 주소에 그대로 남는다) → 세션이 있는가?
            ├ N → A1_LOGIN
            └ Y → onboarded 인가?
                  ├ Y → S1_HOME
                  └ N → A2_TERMS (가입을 중간에 멈춘 계정)
```

## 7. 호스트 플로우

### 7.1 A1_LOGIN → A2_TERMS → A3_PROFILE — 로그인·가입 (A-01 · A-02 · A-03)

```
A1_LOGIN
  ├ [구글로 시작하기] / [카카오로 시작하기]
  │    → 두 버튼 비활성. 누른 버튼은 "{공급자} 계정 확인 중…"
  │    → 목업 인증 0.7초. 계정을 세션(dasiBomAuth)과 가입 이력(dasiBomAccounts)에 기록
  │    └ 그 공급자 계정이 가입 이력에 있고 onboarded 인가?
  │        ├ Y → 토스트 "{이름}님, 다시 만나 반가워요" → S1_HOME
  │        └ N → 토스트 "{공급자} 계정을 연결했어요" → A2_TERMS
  └ [초대 링크로 참여하기] → G1_WELCOME (openId 앨범. 처음 켰다면 '2023년 유럽여행')

A2_TERMS  (진행 바 "1 / 2")
  ├ [약관에 모두 동의합니다] → 필수 3 + 선택 1 일괄 토글
  ├ 개별 체크 — [필수] 만 14세 이상 / 서비스 이용약관 / 개인정보 수집·이용 동의, [선택] 새 소식 받아보기
  ├ [보기] (이용약관 · 개인정보 · 새 소식 세 항목에만) → 토스트 "{항목} 전문을 준비했어요"
  ├ 필수 3개가 모두 체크됐는가?
  │    ├ N → [동의하고 계속하기] 비활성
  │    └ Y → 선택 동의 값을 세션 marketing에 저장 → A3_PROFILE
  └ 뒤로가기 / [다음에 가입할게요] → 세션 삭제(signOut) → A1_LOGIN

A3_PROFILE  (진행 바 "2 / 2")
  ├ 캐릭터 4종(엄마 · 아빠 · 아들 · 딸) 택1, 배경색 8종 택1 — 미리보기 즉시 반영
  ├ 이름 입력 — 공급자 이름으로 미리 채움, 최대 12자
  │    └ 이름이 비어 있는가?
  │        ├ Y → [다시, 봄 시작하기] 비활성
  │        └ N → 이름·캐릭터·색 저장 + onboarded=true
  │              → 토스트 "반가워요, {이름}님. 첫 앨범을 만들어볼까요?" → S1_HOME
  └ 뒤로가기 → A2_TERMS (체크 상태는 처음부터 다시)
```

캐릭터는 `tone`(0~3), 배경색은 `color`(0~7)로 세션에 저장됩니다. 상단 아바타, 홈 카드의 겹친 프로필, 상세 명단, 링크 합류 때 구성원 스토어에 들어가는 내 프로필이 이 값을 씁니다.

### 7.2 S1_HOME — 홈 (B-01 · B-02 · B-03 · B-09)

위에서부터 상단 바, 앨범 배너(한 권씩 크게, 옆으로 넘김 · 배경은 커버 색), 제목 "함께 기억하고 싶은 순간이 있나요?", 카드 [새 앨범 만들기], '내 앨범' 헤딩과 드롭다운 2개, 카드 그리드(2열 · 패브릭 하드커버 4:5 썸네일, 가운데 창에 대표 사진 원본 비율), '기록 Tip' 상자, 우측 하단 ＋, 하단 탭입니다. 배너·목록의 앨범은 호버하면 책등이 보이게 살짝 돌아서고, 누르면 나머지 화면이 어두운 스크림에 가려지는 동안 앨범 한 권이 그 자리에서 4:5 그대로 화면 폭까지 커지고, 가려진 채로 아래 화면이 상세로 바뀐 뒤 표지가 왼쪽 책등을 축으로 천천히 넘어가 그 아래 사진(= 상세 hero, 같은 4:5)이 드러납니다. 표지가 다 넘어가면 오버레이가 녹아 사라집니다(모션 줄이기 설정이면 바로 전환).

| 트리거 | 분기 | 결과 |
|---|---|---|
| 상단 아바타 | — | → `S10_PROFILE` |
| 카드 [새 앨범 만들기] / 우측 하단 ＋ | — | → `S2_CREATE` |
| 앨범 카드 본문 | — | openId = 그 앨범 → `S3_DETAIL` |
| 카드 `···` → 정보 수정 | — | openId = 그 앨범 → `S3E_ALBUM_EDIT` |
| 카드 `···` → 공유 | — | openId = 그 앨범 → `S7_INVITE` (탭으로 들어온 것과 같은 모습. §7.10 (b)) |
| 카드 `···` → 삭제 | 내 역할이 owner인가? | Y → 메뉴에 보인다. 눌러도 토스트 "삭제는 확인 후 진행돼요"만 / N → 메뉴에 없다 |
| 분류 드롭다운 | 전체 / 내가 만든 / 초대받은 (항목마다 개수) | 고른 분류만 남긴다. 토스트 없음 |
| 정렬 드롭다운 | 최근 수정순 / 오래된 순 | 목록 앞뒤만 뒤집는다. 토스트 없음 |
| 하단 탭 | 앨범 / 초대 / 알림 / 나 | `S1_HOME` / `S7_INVITE` / `S9_NOTICES` / `S10_PROFILE` |

```
내 앨범 목록
  └ 참여 중인 앨범이 하나도 없는가?
      ├ Y → "아직 참여 중인 앨범이 없어요" 안내. 드롭다운 숨김
      └ N → 앨범이 2개 이상인가?
            ├ N → 드롭다운 숨김. 카드 1개
            └ Y → 분류 · 정렬 드롭다운 표시
                  └ 분류 결과가 비었는가?
                      ├ Y → "{분류} 앨범이 없어요" + [전체 보기] → 분류를 전체로
                      └ N → 카드 그리드
```

카드에는 커버, 제목(2줄까지), 시작일, 겹친 프로필(나 + 구성원, 최대 3개 + `+n`), 사진 수가 있습니다. 상태 뱃지·역할 칩·진행률은 없습니다. 구성원 중 내 이름과 같은 사람은 겹친 프로필에서 한 번만 셉니다.

### 7.4 S3_DETAIL — 앨범 상세 (B-06 · B-07 · B-08 · C-06 · C-07 · C-08)

위에서부터 1:1 커버(기간 · 제목 · 구성원 이름 줄), 요약 카드, 상위 탭 앨범 · 기록, 하단 고정 [＋ 사진 추가]입니다. 요약 카드에는 사진 수, 목소리 수, [앨범 정보], 그리고 기록 중 사진이 남아 있을 때만 [이어서 기록 남기기]("전체 n장 · 기록 완료 m장 · 기록 중 k장")가 있습니다.

| 트리거 | 분기 | 결과 |
|---|---|---|
| 뒤로가기 | — | → `S1_HOME` (고정. 거쳐온 화면과 무관) |
| 상단 [초대] | — | → `S7_INVITE` (앨범 고정. §7.10 (c)) |
| 구성원 이름 줄 | — | 명단 모달 "기록 중인 사람 n명" (나 포함) |
| 요약 [앨범 정보] | — | → `S3E_ALBUM_EDIT` |
| 요약 [이어서 기록 남기기] | 기록 중 사진이 1장 이상인가? | Y → 표시 → `S3L_RECORD_LIST` / N → 숨김 |
| 하단 [사진 추가] | — | → `S8_UPLOAD` |

이름 줄은 겹친 프로필 최대 3개(나 먼저)와 "나 · 엄마 · 아버지 외 n명"입니다. 모달 첫 줄은 나이고, 만든 사람이면 "이 앨범을 만들었어요", 링크로 들어왔으면 "초대 링크로 참여했어요"가 붙습니다. 그 아래 구성원마다 상태 뱃지(참여 중 / 초대됨 / 다시 초대)가 붙고, 모달에서 재초대는 못 합니다.

상위 탭 '앨범' (읽기):

| 트리거 | 분기 | 결과 |
|---|---|---|
| 사진이 0장 | — | "아직 사진이 없어요. 아래 ‘사진 추가’로 시작해보세요." |
| 사진마다 | 글(`story`)이 있는가? | Y → 글 본문 / N → "아직 글이 없어요…" + [기록 이어가기] → `S4_INTERVIEW` |
| 목소리 행 ▶ | 재생 중인가? | Y → ■ 아이콘 + 토스트 "재생을 멈췄어요" / N → ▶ 아이콘 + 토스트 "{이름}의 목소리를 재생합니다". 소리는 나지 않는다 |

앨범 설명 아래에 사진이 촬영 시각순으로 이어집니다. 사진마다 번호, "날짜 · 장소", 사진, 제목, 글, 목소리 행 순서입니다. 끝에는 "여기까지가 지금까지의 기록이에요."가 있습니다.

상위 탭 '기록' → 하위 탭 4개:

| 하위 탭 | 트리거 | 분기 | 결과 |
|---|---|---|---|
| 사진 | 상태 필터 | 전체 / 기록 중 / 기록 완료 (개수 표시) | 목록을 걸러낸다. 결과가 없으면 "이 상태의 사진이 없어요." |
| 사진 | 사진 타일 | `status`가 기록 완료인가? | Y → `S6_STORY` / N → `S4_INTERVIEW` |
| 목소리 | ▶ | 재생 중인가? | 아이콘 토글 + 토스트. 소리 없음 |
| 목소리 | 연필 아이콘 ({이름}의 목소리 수정) | — | → `S5_VOICE` |
| 글 | 상태 필터 | 전체 / 기록 중 / 기록 완료 | 같은 필터. 헤딩 "완성된 글 n편" |
| 글 | 카드 버튼 | 글(`story`)이 있는가? | Y → [글 수정] → `S6_STORY` / N → [기록 이어가기] → `S4_INTERVIEW` |
| 연대표 | 항목 | `status`가 기록 완료인가? | Y → `S6_STORY` / N → `S4_INTERVIEW` |

사진 타일에는 기록 중 사진에만 "기록 중" 뱃지가 붙습니다. 네 탭 모두 비어 있을 때 안내 문구가 따로 있습니다. 어느 사진을 눌렀는지는 다음 화면에 전달되지 않습니다(§10).

### 7.7 S4_INTERVIEW — 사진 기록 남기기 (C-03)

대상 사진은 스토어의 첫 번째 `기록 중` 사진입니다. 기록 중 사진이 없으면 앨범 첫 사진을 보여줍니다. 사진이 하나도 없으면 "아직 기록할 사진이 없어요. 사진을 먼저 추가해주세요."만 보입니다.

상태는 `question`(0→1→2), `textMode`(글 입력 모드), `answer`입니다.

```
진행 바 "질문 n / 3" · 사진(캡션 날짜 · 시간 · 장소) · 질문 카드 "AI가 사진을 보고 물어봐요"
  질문 3개 고정
    ① 이 사진은 여행 중 언제, 어디에서 찍은 사진인가요?
    ② 그날 가장 기억에 남는 대화는 무엇이었나요?
    ③ 이 순간을 한 문장으로 남긴다면요?
  2 · 3번째 질문에는 '이전 기록' 인용이 붙는다 — 고정 문구 “파리에 도착한 다음 날, 가족들과 작은 식당에서 저녁을 먹었어요.”

  ├ [목소리로 답하기] → S5_VOICE
  ├ [글로 답하기] → 글 입력 모드 (최대 500자, "n / 500")
  │    └ 글이 비어 있는가?
  │        ├ Y → 제출 버튼 비활성
  │        └ N → 제출 ([기록 남기기]. 마지막 질문은 [기록 완성하기])
  │              └ 마지막 질문(3번째)인가?
  │                  ├ N → 다음 질문. 입력을 비우고 선택 모드로 복귀 + 토스트 "기록을 저장하고 다음 질문을 만들었어요"
  │                  └ Y → 토스트 "사진 기록이 완성됐어요" → S6_STORY
  └ [이 질문은 건너뛸게요]
       └ 마지막 질문인가?  N → 다음 질문 (입력 모드와 쓴 글은 그대로) / Y → S3_DETAIL

상단 [나가기] / 뒤로가기 → S3_DETAIL
```

답은 어디에도 저장되지 않습니다. 사진 상태도 바뀌지 않습니다.

### 7.8 S5_VOICE — 목소리로 답하기 (C-04)

대상 사진 규칙은 기록 남기기와 같습니다(첫 기록 중 사진). 질문은 1번 질문 고정입니다.

```
대기 — "버튼을 누르면 실제 녹음이 시작돼요" · "최대 5분까지 녹음할 수 있어요" · [글로 답하기] → S4_INTERVIEW
  [● 마이크] → getUserMedia({audio:true}) + MediaRecorder
    ├ 권한 거부 / 장치 없음 / MediaRecorder 미지원 → 토스트 "마이크 권한을 허용하거나 글로 답해주세요". 대기 유지
    └ 허용 → 녹음 중: 파형 애니메이션 + 타이머 mm:ss + "듣고 있어요. 편하게 이야기해주세요." ([글로 답하기] 숨김. 5분 자동 정지 없음)
         [■ 정지] → Blob → <audio controls> 미리듣기 (실제 재생) · "녹음이 완료됐어요" · "재생해 확인한 뒤 목소리를 남겨주세요"
              ├ [다시 녹음] → 녹음본 폐기(ObjectURL revoke). 타이머 00:00. 대기로
              └ [이 목소리 남기기] → 토스트 "목소리를 안전하게 저장했어요" → S6_STORY (파일은 버려진다)

뒤로가기 → S4_INTERVIEW. 화면을 벗어나면 마이크 트랙 정리
```

### 7.9 S6_STORY — 사진 기록 (글) (C-05 · C-08)

글(`story`)이 있는 사진이 하나라도 있으면 그 사진들만 넘겨 봅니다. 없으면 앨범 사진 전체입니다. 시작은 항상 첫 사진(index 0)이고, 사진이 없으면 "아직 기록이 없어요."만 보입니다.

| 모드 | 트리거 | 결과 |
|---|---|---|
| 공통 | 사진 위 ◀ ▶ | 이전 / 다음 사진. 카운터 "n / N", 날짜 · 시간 · 장소 · 제목 · 글 · 목소리 카드가 함께 바뀐다. 양 끝에서는 그쪽 버튼을 숨긴다 |
| 보기 | 상단 [수정] | 수정 모드 |
| 보기 · 수정 | 목소리 카드 | ▶ / ■ 아이콘 토글 + 토스트 "{이름}의 목소리를 재생합니다" / "재생을 멈췄어요". 소리 없음. 목소리 없는 사진은 "가족의 목소리 · 아직 목소리가 없어요" |
| 수정 | 제목 입력 · 본문 입력 | 비제어(defaultValue). 고쳐도 값이 잡히지 않는다 |
| 수정 | 문체 [따뜻하게] [담백하게] [회고록처럼] | 선택 표시만. 저장 토스트 문구에만 쓰인다 |
| 수정 | 하단 [기록 저장하기] | 보기 모드 복귀 + 토스트 "{문체} 스타일로 기록을 저장했어요". 아무 데도 반영되지 않는다 |
| 수정 | 상단 [취소] | 보기 모드 |
| 공통 | 뒤로가기 | → `S3_DETAIL` |

태그 4개, 인용 카드, 하단의 "이 글은 가족이 남긴 기록을 모아 AI가 정리했어요." 문구는 고정값입니다.

### 7.10 S7_INVITE — 초대 (D-01 ~ D-06)

들어온 길에 따라 네 가지 모습입니다.

| 진입 경로 | `justCreated` | 앨범 고정(`locked`) | 상단 뒤로가기 | 하단 탭 | 앨범 선택기 | 나가는 길 |
|---|---|---|---|---|---|---|
| (a) 하단 탭 '초대' | false | false | 없음 | 있음 | 앨범 2개 이상이면 세로 라디오 리스트 | 하단 탭 |
| (b) 홈 `···` → 공유 | false | false | 없음 | 있음 | (a)와 같음. 그 앨범이 미리 선택 | 하단 탭 |
| (c) 상세 [초대] | false | true | 있음 (→ 상세) | 없음. 화면을 꽉 채운다 | 숨김 | 뒤로가기 |
| (d) 앨범 생성 직후 | true | true | 없음 | 없음. 화면을 꽉 채운다 | 숨김 | 우측 상단 ✕ → `S1_HOME` / [앨범에 사진 추가] → `S8_UPLOAD` |

(b)가 (a)와 같은 이유는 홈→초대가 탭 홈 사이의 이동이라 `history`가 비고, 뒤로가기는 `history`가 있을 때만 붙기 때문입니다(`src/App.tsx`). 기본 선택 앨범은 `openId`(마지막으로 열어 둔 앨범)입니다. 선택기 행은 커버 · 제목 · 시작일 · 사진 n장 · 라디오이고, 3개 반까지 보이고 그 아래는 안에서 스크롤합니다.

머리말은 (d)에서 "앨범을 만들었어요" + "이제 함께 기록할 가족을 초대해보세요. 링크를 받은 가족은 가입 없이 참여할 수 있어요." + 방금 만든 앨범 한 줄(커버 · 제목 · 기간)입니다. 그 외에는 "우리의 추억을 기록해요" + "링크를 공유하면 회원가입 없이 사진을 추가할 수 있어요."입니다.

```
참여 중인 앨범이 하나도 없는가?
  ├ Y → "아직 참여 중인 앨범이 없어요" + [새 앨범 만들기] → S2_CREATE  (뒤로가기가 있으면 상단 바, 없으면 하단 탭)
  └ N → 링크 카드 "‘{앨범}’ 참여 링크"  링크 = {origin}{pathname}?invite={코드}
        └ 링크가 만료됐는가? (발급 시각 + 7일 ≤ 지금)
            ├ N → 라벨 오른쪽에 "D-{n}" (n=0이면 "D-DAY") + ⓘ. ⓘ를 누르면 한 줄 말풍선 "초대 링크 유효기간은 일주일이에요. {월 일}까지 쓸 수 있고, 만료되면 새로 만들 수 있어요." + 닫기. 닫기나 바깥을 누르면 닫힘
            │     ├ [복사] → 클립보드 API. 실패하면 textarea + execCommand('copy') → 토스트 "참여 링크를 복사했어요"
            │     └ [공유하기] → navigator.share 가 있는가?
            │            ├ Y → OS 공유 시트 (제목 "{앨범}에 초대해요"). 취소하면 아무 일 없음
            │            └ N → [복사]와 같은 동작
            └ Y → 뱃지 "만료됨". 링크 취소선. [복사] 비활성. "{만료일}에 만료됐어요. 링크를 새로 만들면 다시 초대할 수 있어요."
                  └ [링크 새로 만들기] ([공유하기] 자리) → 코드 · 발급 시각 교체. 구성원은 그대로
                        → 토스트 "새 참여 링크를 만들었어요. 7일간 쓸 수 있어요" → 카드가 유효 상태로

(d)에만: [앨범에 사진 추가] → S8_UPLOAD

기록 중인 사람 {n}명 (나는 빼고 센다) · "앨범 구성원은 누구나 새 구성원을 초대할 수 있어요"
  ├ 구성원 없음 → "아직 초대한 가족이 없어요."
  ├ 참여 중 / 초대됨 → 상태 뱃지 ("기록 n개" 같은 부속 문구는 시드 고정값)
  └ 다시 초대 → [다시 초대] 버튼 → 토스트 "{이름}에게 초대를 다시 보냈어요"
```

새로 발급한 코드와 새 앨범의 코드는 새로고침 뒤 부팅 분기에서 인식되지 않습니다(§6은 시드 상수만 봅니다).

### 7.11 S8_UPLOAD — 사진 추가하기 (C-01)

```
[내 컴퓨터에서 사진 고르기]  (터치 기기는 "폰에 저장된 사진 불러오기")
  └ 데스크톱 크로미움(File System Access API)인가?
      ├ Y → 파일 선택창. 다운로드 폴더부터, 여러 장 ("다운로드 폴더부터 열려요 · 여러 장 선택 가능"). 창을 닫으면 아무 일 없음
      └ N → 기본 파일 input (image/*, 여러 장) ("JPG, PNG, WebP · 여러 장 선택 가능")
  → 이미지(image/*)만 남기고 나머지는 조용히 제외
  → 파일마다 사진으로 변환: 제목 = 파일명(확장자 제외), 촬영 시각 = 파일 수정 시각(EXIF 안 읽음), 장소 = "위치 없음", 상태 = 기록 중, src = blob URL
  → 이미 고른 것과 합쳐 촬영 시각순 정렬

미리보기 3열 그리드 (뱃지 "업로드 준비") · "촬영이 이른 사진부터 정렬했어요. 이 순서대로 기록을 남기게 돼요."
  ├ 항목 [×] → 목록에서 제거
  └ 고른 사진이 0장인가?
      ├ Y → 버튼 "사진을 먼저 골라주세요" (비활성)
      └ N → [사진 n장 추가하고 기록 시작]
            → 사진 스토어에 실제 추가 (메모리. 촬영순 재정렬) → 토스트 "사진 n장을 촬영 시간순으로 정리했어요" → S4_INTERVIEW

뒤로가기 → S3_DETAIL (고른 사진은 버린다)
```

### 7.12 S9_NOTICES — 알림 (E-01)

## 8. 게스트 플로우 (D-08 · D-09)

### 8.1 G1_WELCOME — 초대 랜딩

```
링크가 만료됐는가? (inviteExpired)
  ├ Y → "링크가 만료됐어요" + "참여 링크는 만든 날부터 7일 동안만 쓸 수 있어요. 초대한 가족에게 새 링크를 부탁해주세요."
  │     └ [닫기] → 주소에서 ?invite= 제거 → S1_HOME
  └ N → 앨범 커버 (캡션 "하연님이 초대했어요" — 고정 문구) · "가족 앨범 초대" · 앨범 제목 · 참여 3단계 안내
        ├ [이 앨범에 참여하기] → G2_INFO
        └ [지금은 참여하지 않을게요] → 주소에서 ?invite= 제거 → S1_HOME
```

홈으로 나갈 때 세션 검사가 없습니다. 비회원도 홈에 도달하고, 시드 '내 앨범' 3개가 그대로 보입니다.

### 8.2 G2_INFO — 참여자 정보

```
닉네임(필수) · 가족 관계(필수: 어머니 / 아버지 / 형제·자매 / 친척) · "사진·음성·기록 처리에 동의합니다" 체크(필수)
[참여 시작하기]
  └ 셋 중 하나라도 비었는가? (닉네임은 공백만 넣어도 통과)
      ├ Y → 토스트 "이름·관계·동의를 모두 확인해주세요". 화면 유지
      └ N → localStorage.dasiBomGuest = 닉네임 → G3_ANSWER  (관계 · 동의는 저장 안 됨)

뒤로가기 → G1_WELCOME
```

### 8.3 G3_ANSWER — 기록 남기기

```
진행 바 "사진 n / N" (N = 그 앨범의 사진 수. 시드는 3~4장) · 사진(캡션 날짜 · 시간 · 장소)
질문 카드 "이 사진에 대해 궁금해요" — 고정 3문장을 순서대로 돌려 쓴다 (4장째부터 반복)
  ① 이때 가족들은 어떤 기분이었나요?
  ② 이날 기억나는 대화나 음식이 있나요?
  ③ 여행 마지막 날, 가장 아쉬웠던 건 무엇인가요?
  (앨범에 사진이 없으면 "아직 이 앨범에 사진이 없어요. 초대한 가족에게 알려주세요."만 표시)

  ├ 글 입력 (최대 500자)
  │    └ 비어 있는가?
  │        ├ Y → 제출 버튼 비활성
  │        └ N → 제출 ([기록 저장하고 다음 사진]. 마지막 사진은 [기록 모두 제출하기])
  │              └ 마지막 사진인가?
  │                  ├ N → 다음 사진. 입력 비움 + 토스트 "기록을 저장했어요"
  │                  └ Y → G4_DONE
  └ [이 사진은 건너뛸게요]
       └ 마지막 사진인가?  N → 다음 사진 (쓴 글은 그대로) / Y → G4_DONE

뒤로가기 → G2_INFO
```

답은 저장되지 않습니다. 목소리 답변은 랜딩의 안내 문구에만 있고 화면에는 글 입력만 있습니다.

### 8.4 G4_DONE — 참여 완료

```
"{닉네임}님의 기록" · "소중한 기억을 남겨주셔서 고마워요"
"사진 3장에 남긴 기록이 하연님에게 전달됐어요…" · 기록한 사진 3장 / 글로 남긴 기록 2개  — 전부 고정값
  ├ [기록 다시 보기] → G3_ANSWER (첫 사진부터. 입력 초기화)
  └ [참여 마치기] → 주소에서 ?invite= 제거 → S1_HOME
```

## 10. 미구현 / 알아둘 것

플로우를 그릴 때 헷갈리기 쉬운 것만 골랐습니다. 서버 연동 전에 손봐야 할 목록은 [개발현황](./개발현황.md)에 있습니다.

- 어느 사진을 눌렀는지 다음 화면에 전달되지 않는다. 앱 상태에 앨범 id만 있고 사진 id가 없다. 기록 남기기·목소리는 첫 '기록 중' 사진을, 글은 글이 있는 첫 사진을 연다.
- 답·목소리·글은 저장되지 않는다. 토스트만 뜬다.
- 사진 상태를 '기록 완료'로 바꾸는 코드가 없다. 3번째 답을 내도 상태와 글이 그대로라, 이어지는 글 화면은 방금 기록한 사진이 아니라 글이 있는 첫 사진을 보여준다.
- 글 화면의 문체 버튼은 토스트 문구만 바꾼다. 제목·본문을 고쳐도 저장되지 않는다.
- 목소리 재생은 아이콘 토글 + 토스트다. 소리가 나는 곳은 녹음 직후 미리듣기 하나다.
- 앨범 삭제는 만든 사람에게만 메뉴가 보이고, 눌러도 토스트만 뜬다.
- 알림은 고정 2건이고 항상 마지막으로 연 앨범으로 간다.
- 새로 발급한 초대 코드와 새 앨범의 코드는 새로고침 뒤 인식되지 않는다. 부팅 분기가 시드 상수만 본다.
- 촬영 시각은 EXIF가 아니라 파일 수정 시각이다. 장소는 "위치 없음". 새 앨범의 회색 커버는 사진을 올려도 바뀌지 않는다.
- 구성원 수가 두 화면에서 다를 수 있다. 초대 화면은 나를 빼고, 상세 모달은 나를 더해 센다. 시드 앨범처럼 명단에 내 이름이 없으면 상세가 1 크다.
- 게스트 흐름을 마치면 세션 없이 홈에 도달한다. 완료 화면의 "3장 / 2개"와 "하연님이 초대했어요"는 고정 문구다.
- 건너뛰기(기록 남기기·게스트)는 쓰던 글을 지우지 않는다.
- 로그인은 목업이다. 실패 경로가 없고, 구글과 카카오는 별개 계정이다.
