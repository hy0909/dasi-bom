# 다시, 봄 — UX 플로우 기획서

> UX 플로우 다이어그램 생성용 입력 문서. 화면 단위 ID, 분기 조건(Y/N), 역할, 상태, 예외 경로를 그대로 노드/엣지로 옮길 수 있게 정리했습니다.
> 기준 코드: `src/App.tsx`, `src/screens/*` (2026-09-15)

## 1. 역할 (Role)

| 역할 | 설명 | 인증 |
|---|---|---|
| `HOST` | 앨범 소유자. 앨범 생성·편집·초대 권한 | 구글 / 카카오 소셜 로그인 후 가입 온보딩 완료 (프로토타입은 목업 인증) |
| `GUEST` | 초대 링크로 들어온 가족. 답변만 가능 | 회원가입 없음. 닉네임만 `localStorage.dasiBomGuest` 에 저장 |

## 2. 전역 상태 (State)

| 상태 키 | 값 | 보관 위치 |
|---|---|---|
| `screen` | 19개 화면 ID 중 하나 | React state (`src/App.tsx`) |
| `history` | 방문한 화면 스택. 뒤로가기가 실제로 거쳐온 화면으로 돌아가는 근거 | React state |
| `album` | 앨범 한 벌 — 제목·시작일·종료일·설명·상태 (`src/data/album.ts`) | React state |
| `ready` | 초기 부팅 완료 여부. `false` 동안 부팅 화면 | React state |
| `dasiBomGuest` | 게스트 닉네임 | `localStorage` |
| `dasiBomAuth` | 현재 로그인 세션 `Account` (provider·email·name·tone·marketing·onboarded). `tone` 은 프로필 캐릭터 인덱스 | `localStorage` |
| `dasiBomAccounts` | 가입 이력. provider 별 계정 1개 — 재로그인 시 신규/기존 판단 | `localStorage` |
| `?invite=<코드>` | 앨범별 초대 코드 (EU23 · JEJU · SUMMER · SEA) | URL 쿼리스트링 |

> 인증 상태는 `src/lib/auth.ts` 한 곳에서 관리하고 `useSession()` 으로 구독합니다.
> 프로토타입이라 실제 OAuth 대신 0.7초 지연 목업(`mockAuthorize`)을 씁니다.

## 1.1 용어

| 용어 | 뜻 |
|---|---|
| 앨범 | 사진과 기록을 모으는 상위 단위. 제목·기간·설명·상태와 고유 초대 코드를 가진다 |
| 기록 | 사진 한 장에 붙는 자식 단위. 가족의 답변을 AI가 한 편으로 정리한 결과 |
| 답변 | 사진 한 장에 대한 AI 질문(3개)에 남긴 음성 또는 글. 기록의 재료 |
| 참여 링크 | 앨범마다 다른 초대 링크(`?invite=<코드>`). 참여자 목록도 앨범 단위로 묶인다 |
| 내 앨범 | 내가 참여 중인 앨범. 내가 만든 앨범(`owner`)과 링크를 타고 합류한 앨범(`member`)이 함께 담긴다 |

## 2.1 표기 규칙

- 사진 날짜는 `2023년 7월 11일`, 시간은 `오후 7시 40분` 형식입니다. 사진 데이터의 촬영 시각(`takenAt`)에서 만듭니다.
- 앨범 기간은 `2023년 7월 10일 - 7월 17일` 형식이고, 같은 해면 뒤쪽 연도를 생략합니다.
- 연대표처럼 자리가 좁은 곳은 `7. 11` 로 줄입니다.
- 사진 위 캡션은 `날짜 · 시간 · 장소` 순서입니다.

## 3.1 네비게이션 규칙

- 하단 탭 4개(`S1_HOME` · `S7_INVITE` · `S9_NOTICES` · `S10_PROFILE`)는 **탭 홈**입니다. 상단 바와 뒤로가기가 없고, 제목은 본문 헤딩으로 둡니다.
- 나머지 화면은 밀려 들어간 페이지라 상단 바에 뒤로가기가 있습니다.
- 뒤로가기는 화면마다 목적지를 고정하지 않고 `history` 스택에서 꺼냅니다. 같은 화면이라도 들어온 길에 따라 돌아가는 곳이 달라집니다. (예: `S7_INVITE` 는 탭으로 들어오면 홈, 앨범 상세에서 들어오면 상세)
- 탭끼리 이동할 때는 기록을 쌓지 않습니다. 탭은 서로의 상위 화면이 아닙니다.
- 새 앨범 만들기는 하단 탭 가운데가 아니라 홈 우측 하단의 원형 플로팅 버튼입니다.

## 4. 진입 분기 (Entry)

```
앱 로드 → S0_BOOT
  └ URL 에 아는 초대 코드(?invite=…)가 있는가?
      ├ Y → 링크가 만료됐는가? (발급일 + 7일)
      │      ├ Y → G1_WELCOME  (만료 안내 · 회원·비회원 모두 참여 불가)
      │      └ N → 로그인을 마친 회원(onboarded)인가?
      │            ├ Y → 앨범 참여자 + 내 앨범 목록에 합류 → 쿼리스트링 제거 → S3_DETAIL
      │            └ N → G1_WELCOME  (게스트 플로우 · 가입 없이 답변만)
      └ N → dasiBomAuth 세션이 있는가?
            ├ N → A1_LOGIN                (비로그인)
            └ Y → onboarded 가 true 인가?
                  ├ Y → S1_HOME           (기존 회원)
                  └ N → A2_TERMS          (가입을 중간에 멈춘 계정 — 이어서 진행)
```

## 5. 호스트 플로우

### 5.0 A1_LOGIN → A2_TERMS → A3_PROFILE — 로그인·가입

```
A1_LOGIN
  ├ [구글로 시작하기] / [카카오로 시작하기]
  │     → 버튼 로딩 "{공급자} 계정 확인 중…" (두 버튼 모두 비활성)
  │     → 목업 인증 0.7초
  │          └ dasiBomAccounts 에 해당 공급자 계정이 있고 onboarded 인가?
  │              ├ Y → 토스트 "{이름}님, 다시 만나 반가워요" → S1_HOME
  │              └ N → 토스트 "{공급자} 계정을 연결했어요" → A2_TERMS
  └ [초대 링크로 참여하기] → G1_WELCOME (게스트 뷰 미리보기)

A2_TERMS  (1 / 2)
  ├ [약관에 모두 동의합니다] → 필수 3 + 선택 1 일괄 토글
  ├ 개별 체크 (필수: 만 14세 이상 · 이용약관 · 개인정보 / 선택: 새 소식)
  ├ 각 항목 [보기] → 토스트 (전문 화면 미구현)
  ├ 필수 3개가 모두 체크됐는가?
  │   ├ N → [동의하고 계속하기] 비활성
  │   └ Y → 선택 동의 여부를 세션(marketing)에 저장 → A3_PROFILE
  └ [다음에 가입할게요] / 뒤로가기 → 세션 정리(signOut) → A1_LOGIN

A3_PROFILE  (2 / 2)
  ├ 프로필 캐릭터 4종(엄마·아빠·아들·딸)과 배경색 8종 중 각각 택1 (미리보기 즉시 반영)
  ├ 이름 입력 (공급자 이름으로 프리필, 최대 12자)
  │   └ 이름이 비어 있는가?
  │       ├ Y → [다시, 봄 시작하기] 비활성
  │       └ N → onboarded=true 저장 → 토스트 "반가워요, {이름}님…" → S1_HOME
  └ 뒤로가기 → A2_TERMS (동의 상태는 다시 입력)
```

가입이 끝나면 상단 아바타와 앨범 카드의 겹친 프로필이 고른 캐릭터를 따라갑니다. 캐릭터는 계정의 `tone` 값(0~4)으로 저장합니다.

### 5.1 S1_HOME — 홈

| 트리거 | 분기 | 결과 |
|---|---|---|
| 새 앨범 만들기 카드 | — | → `S2_CREATE` |
| 앨범 카드 본문 클릭 | — | → `S3_DETAIL` |
| 앨범 카드 더보기 `···` | 정보 수정 | → `S3E_ALBUM_EDIT` |
| | 공유 | → `S7_INVITE` |
| | 삭제 | 토스트 (확인 절차 미구현) |
| 정렬 버튼 | 현재 최근순인가? | Y → 오래된 순 / N → 최근 수정순. 둘 다 토스트 |
| 하단 네비 | 앨범 / 초대 / 알림 / 나 | `S1_HOME` / `S7_INVITE` / `S9_NOTICES` / `S10_PROFILE` |
| 우측 하단 플로팅 `＋` | — | → `S2_CREATE` |

‘내 앨범’은 **내가 참여 중인 앨범**입니다. 내가 만든 앨범과 초대 링크를 타고 합류한 앨범이 한 목록에 섞이고,
참여하지 않은 앨범은 보이지 않습니다. 링크로 들어온 앨범은 카드 왼쪽 위에 `{초대한 사람}의 앨범`
(초대한 사람을 모르면 `초대받은 앨범`) 칩을 답니다. 참여 중인 앨범이 없으면 목록 자리에 안내 카드를 두고
정렬 버튼을 숨깁니다.

앨범 카드에는 상태 뱃지(기록 중 / 완료), 제목, 기간, 함께하는 사람들의 겹친 프로필, 사진 수를 표시합니다. 진행률(%)은 쓰지 않습니다.

### 5.2 S2_CREATE — 새 앨범 만들기

```
제목 입력
  └ 제목이 비어 있는가?
      ├ Y → [앨범 만들기] 버튼 비활성 (제출 불가)
      └ N → 제출 가능

대표 사진 선택
  └ 선택한 파일이 이미지인가?
      ├ Y → 미리보기 표시
      └ N → 토스트 "이미지 파일만 선택해주세요" (파일 무시, 화면 유지)

제출 → 버튼 "앨범을 만들고 있어요…" → 0.5초 후 S3_DETAIL
       입력한 제목·시작일·종료일·설명이 앨범에 저장되고, 상태는 '기록 중'으로 시작
```

### 5.3 S3_DETAIL — 앨범 상세

요약 카드에 앨범 상태 뱃지(기록 중 / 완료)와 남은 답변 안내를 둡니다. 상태가 '완료'면 [이어서 기록 남기기]를 감춥니다.

| 탭 | 트리거 | 분기 | 결과 |
|---|---|---|---|
| 사진 | 사진 타일 | 첫 번째 사진(기록 완성)인가? | Y → `S6_STORY` / N → `S4_INTERVIEW` |
| 사진 | 정렬 버튼 | 촬영일순 ↔ 진행 상태순 | 목록 재정렬 + 토스트 |
| 목소리 | 재생 버튼 | 이미 재생 중인가? | Y → 정지 / N → 재생. 둘 다 토스트 |
| 기록 | 기록 카드 | — | → `S6_STORY` |
| 연대표 | 타임라인 항목 | 첫 번째 항목인가? | Y → `S6_STORY` / N → `S4_INTERVIEW` |

| 그 외 트리거 | 결과 |
|---|---|
| 요약 카드 [이어서 기록 남기기] | 상태가 '기록 중'일 때만 노출 → `S4_INTERVIEW` |
| 요약 카드 [앨범 정보] | → `S3E_ALBUM_EDIT` |
| 상단 [가족 초대] | → `S7_INVITE` |
| 플로팅 [＋ 사진 추가] | → `S8_UPLOAD` |
| 뒤로가기 | → 직전 화면 (`history` 스택) |

### 5.3.1 S3E_ALBUM_EDIT — 앨범 정보

앨범을 만든 사람만 들어옵니다. 만들 때 입력한 값이 그대로 채워집니다.

```
제목 · 시작일 · 종료일 · 짧은 설명 · 상태(기록 중 / 완료)
  └ 제목이 비었거나 바뀐 값이 없는가?
      ├ Y → [저장하기] 비활성
      └ N → 저장 → 토스트 "앨범 정보를 저장했어요" → 직전 화면

상태를 '완료'로 두면 앨범 상세에서 답변 이어하기 버튼이 사라집니다. 되돌릴 수 있습니다.
뒤로가기 → 직전 화면 (변경 사항 버림)
```

> 상태는 답변 수로 자동 판정하지 않습니다. 앨범을 만든 사람이 직접 고르는 값입니다.

### 5.4 S4_INTERVIEW — 사진 기록 남기기

상태: `question` 0→1→2 (3단계), `textMode` (음성/글 선택).

```
질문 n 표시 (n>0 이면 이전 답변 인용 노출)
  ├ [목소리로 답하기] → S5_VOICE
  ├ [글로 답하기] → textarea 모드 (최대 500자)
  │     └ 답변이 비어 있는가?
  │         ├ Y → 제출 버튼 비활성
  │         └ N → 제출
  │              └ 마지막 질문(n=2)인가?
  │                  ├ Y → 토스트 "사진 기록이 완성됐어요" → S6_STORY
  │                  └ N → 다음 질문으로, 답변 초기화 + 토스트
  └ [이 질문은 건너뛸게요]
        └ 마지막 질문인가?  Y → S3_DETAIL / N → 다음 질문

상단 [나가기] / 뒤로가기 → S3_DETAIL
```

### 5.5 S5_VOICE — 목소리로 답하기 (예외 경로 포함)

```
[● 녹음] 클릭 → navigator.mediaDevices.getUserMedia({audio:true})
  ├ 권한 거부 / 장치 없음 (예외)
  │     → 토스트 "마이크 권한을 허용하거나 글로 답해주세요"
  │     → 화면 유지 (대기 상태로 복귀)
  └ 권한 허용
        → 녹음 중: 파형 애니메이션 + 타이머 mm:ss (최대 5분 안내)
        → [■ 정지] → Blob 생성 → 미리듣기 플레이어 노출
             ├ [다시 녹음] → 녹음본 폐기(ObjectURL revoke), 타이머 0으로
             └ [이 목소리 남기기] → 토스트 저장 완료 → S6_STORY

[글로 답하기] (대기 상태에서만 노출) → S4_INTERVIEW
뒤로가기 → S4_INTERVIEW · 화면 이탈 시 마이크 트랙 정리
```

### 5.6 S6_STORY — 사진 기록

| 모드 | 트리거 | 결과 |
|---|---|---|
| 보기 | 원본 목소리 카드 | 재생 ↔ 정지 토글 + 토스트 |
| 보기 | 상단 [수정] | 수정 모드로 전환 |
| 수정 | 문체 선택 | 따뜻하게 / 담백하게 / 회고록처럼 중 택1 |
| 수정 | [기록 저장하기] | 보기 모드 복귀 + 토스트 "{문체} 스타일로 기록을 저장했어요" |
| 수정 | 상단 [취소] | 편집 내용 버리고 보기 모드 |
| 공통 | 사진 위 좌우 버튼 | 이전/다음 사진으로 이동. 사진·카운터·날짜·시간·장소·제목이 함께 바뀜. 양 끝에서는 해당 버튼을 감춤 |
| 공통 | 뒤로가기 | → `S3_DETAIL` |

### 5.7 S7_INVITE — 가족 초대하기

```
초대는 앨범 단위다 — 앨범마다 코드가 다르고 참여자 목록도 따로 관리한다.
선택기에는 내가 참여 중인 앨범만 올라온다. 하나도 없으면 링크 대신 [새 앨범 만들기] 안내를 둔다.

  ├ 하단 탭으로 들어옴 → 앨범 선택기 노출, 첫 앨범이 기본값
  └ 앨범 상세의 [초대]로 들어옴 → 그 앨범으로 고정(선택기 숨김) + 뒤로가기 있는 상단 바

선택한 앨범의 링크: {origin}{pathname}?invite={앨범 코드}

[복사]
  └ navigator.clipboard 사용 가능한가?
      ├ Y → 클립보드 복사
      └ N → textarea + execCommand('copy') 폴백
  → 토스트 "실제 가족 참여 링크를 복사했어요"

[공유하기]
  └ navigator.share 지원하는가?
      ├ Y → OS 공유 시트  (사용자가 취소하면 아무 동작 없음)
      └ N → 복사 폴백

참여자 목록 (상태는 세 가지)
  ├ 참여 중  — 답변을 남기고 있는 가족 (주황 뱃지)
  ├ 초대됨   — 초대는 갔고 답을 기다리는 중 (기본 뱃지)
  └ 다시 초대 — 초대가 전달되지 않음. 뱃지가 아니라 재발송 버튼
        └ 클릭 → 토스트 "{이름}에게 초대를 다시 보냈어요"

탭 홈이라 뒤로가기가 없습니다. 하단 탭으로 이동합니다.
```

### 5.8 S8_UPLOAD — 사진 추가하기

```
  └ 이미지 파일만 통과, 그 외는 조용히 제외
선택 목록

```

## 6. 게스트 플로우

### 6.1 G1_WELCOME — 초대 랜딩

```
초대자·앨범 제목·참여 3단계 안내 노출
  ├ [이 앨범에 참여하기] → G2_INFO
  └ [지금은 참여하지 않을게요]
        → URL 쿼리스트링 제거(history.replaceState) → S1_HOME
```

### 6.2 G2_INFO — 참여자 정보

```
닉네임(필수) · 가족 관계 선택(필수) · 처리 동의 체크(필수)
제출
  └ 셋 중 하나라도 비었는가?
      ├ Y → 토스트 "이름·관계·동의를 모두 확인해주세요" (화면 유지)
      └ N → localStorage.dasiBomGuest = 닉네임 → G3_ANSWER

뒤로가기 → G1_WELCOME
```

### 6.3 G3_ANSWER — 기록 남기기 (사진 3장 순차)

```
사진 n (0,1,2) + AI 질문 표시, 진행률 n+1 / 3
  ├ 답변이 비어 있는가?
  │   ├ Y → 제출 버튼 비활성
  │   └ N → 제출
  │        └ 마지막 사진(n=2)인가?
  │            ├ Y → G4_DONE
  │            └ N → 다음 사진, 입력 초기화 + 토스트 "답변을 저장했어요"
  └ [이 사진은 건너뛸게요]
        └ 마지막 사진인가?  Y → G4_DONE / N → 다음 사진

뒤로가기 → G2_INFO
```

### 6.4 G4_DONE — 참여 완료

```
"{닉네임}님의 기록" + 답변한 사진 3장 / 텍스트 답변 2개 요약
  ├ [답변 다시 보기] → G3_ANSWER (처음 사진부터)
  └ [참여 마치기] → URL 쿼리스트링 제거 → S1_HOME
```

## 8. 미구현 / 확인 필요

- 앨범 삭제에 확인 모달이 없습니다. 현재는 토스트만 표시합니다.
- 앨범 상태는 사람이 직접 고릅니다. 사진·답변 수로 자동 전환하는 규칙은 정의돼 있지 않습니다.
- 앨범은 한 벌만 있습니다. 목록·여러 앨범 관리는 범위 밖입니다.
- 초대 링크 만료(2026-09-28) 후 접근 시 동작이 정의돼 있지 않습니다.
- AI 정리 실패, 업로드 실패 등 서버 오류 경로가 없습니다. 프론트 프로토타입 범위 밖입니다.
- 게스트가 목소리로 답하는 경로는 안내 문구에만 있고 화면은 텍스트 입력만 제공합니다.
- 로그인은 목업입니다. 실제 Google Identity Services / Kakao SDK 연동, 토큰 검증, 서버 세션은 범위 밖입니다.
  (`src/lib/auth.ts` 의 `mockAuthorize()` 한 곳만 실제 SDK 호출로 교체하면 나머지 플로우는 그대로 씁니다.)
- 소셜 로그인 실패 경로(사용자 취소, 팝업 차단, 네트워크 오류)는 목업이라 발생하지 않아 화면이 없습니다.
- 약관 전문 화면은 토스트만 있습니다.
- 같은 사람이 구글과 카카오로 각각 로그인하면 별개 계정으로 취급합니다. 계정 통합은 정의돼 있지 않습니다.
