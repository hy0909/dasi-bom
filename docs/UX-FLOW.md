# 다시, 봄 — UX 플로우 기획서

UX 플로우 다이어그램(FigJam)을 그리기 위한 입력 문서입니다. 화면 ID는 노드로, 분기 조건(Y/N)·역할·상태·예외 경로는 엣지로 그대로 옮길 수 있게 정리했습니다. 용어와 기능 ID(A-01~E-03)는 [기능명세서](./기능명세서.md)와 같습니다.

기준 코드 `dd8647e` (2026-09-18). 실행은 `npm run dev`. (지금: 초대 링크를 화면에서 확인할 때는 주소 뒤에 `?invite=SUMMER`(유효) · `?invite=JEJU`(만료) · `?invite=SEA`(아직 내 앨범이 아닌 앨범)를 붙인다.)

## 0. 읽는 법 — 표기 규칙

이 문서는 두 가지를 한 자리에 적습니다. 섞어 읽으면 안 되므로 줄마다 표시를 답니다.

| 표기 | 뜻 |
|---|---|
| 표시 없는 줄 | **그려야 할 플로우.** 아래 확정된 백엔드 동작을 기준으로 한다. FigJam에는 이쪽만 그린다 |
| `(지금: …)` | **지금 프로토타입.** 기준 코드의 화면이 실제로 하는 일. 그리지 않는다. 화면을 열어 확인할 때만 본다 |
| `(미정: …)` | 백엔드도 화면도 아직 정하지 않은 자리. 그리기 전에 답을 받아야 한다 |

확정된 백엔드 동작 — 플로우는 여기에 맞춥니다.

1. 답변·음성 파일·STT 결과·AI가 뽑은 사실(facts)·글(story)은 모두 DB와 스토리지에 저장된다.
2. 질문은 사진을 올릴 때 기본 질문이 만들어지고, 그 뒤 AI가 질문을 바꾸거나 꼬리질문을 더할 수 있다. **질문 수는 고정이 아니다.**
3. 모든 질문에 답하지 않아도 된다. **제출된 답변이 분석되면 글이 만들어진다.**
4. 게스트도 DB에 참여자로 저장되고 HttpOnly 세션 쿠키를 받는다. **목소리로도 답할 수 있다.**
5. 초대 링크는 `/invite/<긴 랜덤 토큰>` 경로이고, 발급일부터 7일 동안 유효하다.

이 다섯 가지가 플로우 모양을 바꾸는 자리는 셋입니다. 기록 흐름(§7.6~§7.8), 게스트 흐름(§8), 진입 분기(§6). 나머지 절은 화면 구성과 이동 규칙이라 지금 프로토타입과 크게 다르지 않습니다.

## 1. 역할

| 역할 | 누구인가 | 인증 | 하는 일 |
|---|---|---|---|
| `HOST` | 가입을 마친 회원 | 구글 / 카카오 로그인 + 약관·프로필 가입 | 앨범 만들기·정보 수정, 사진 추가, 기록, 초대, 링크로 다른 앨범에 합류 |
| `GUEST` | 초대 링크로 들어온 비회원 | 참여자 정보를 내면 서버가 참여자로 저장하고 HttpOnly 세션 쿠키를 내준다 (지금: 인증이 없고 닉네임만 `localStorage.dasiBomGuest`에 남는다) | 사진마다 목소리·글로 기록 (지금: 글만) |

게스트도 앨범 구성원이므로 구성원 명단에 함께 나옵니다 — 상세의 명단 모달, 초대 화면의 목록, 홈 카드의 겹친 프로필 셋 다. (지금: 게스트는 어느 명단에도 들어가지 않는다. 명단에 늘어나는 것은 링크로 합류한 회원뿐이다.)

회원은 앨범마다 만든 사람(`owner`)과 링크로 들어온 사람(`member`)으로 나뉩니다. 이 구분이 쓰이는 곳은 홈의 분류 필터, 홈 카드의 삭제 메뉴, 상세 명단 모달의 내 줄 문구 세 곳입니다.

## 2. 용어

| 용어 | 뜻 |
|---|---|
| 앨범 | 여행이나 시기 하나. 사진·목소리·글이 여기에 묶인다. 앨범 자체에는 상태가 없다. 사진은 한 앨범에 20장까지 |
| 구성원 | 앨범에 참여 중인 사람. 만든 사람(owner)·링크로 들어온 회원(member)·게스트를 모두 센다. 화면 문구는 '기록 중인 사람' |
| 기록 | 가족이 사진에 남기는 목소리·글, 그리고 AI가 그걸 모아 정리한 글. 화면에서는 '답변'이라는 말을 쓰지 않는다 |
| 기록 상태 | 사진 한 장 단위. `기록 전` / `기록 완료` 둘뿐. 목소리든 글이든 하나라도 남았으면 기록 완료 |
| 질문 | 사진마다 붙는 물음. 사진을 올릴 때 기본 질문이 생기고, AI가 바꾸거나 꼬리질문을 더한다. 수가 정해져 있지 않다 (지금: 화면에 박아 둔 3문장 고정) |
| 초대 링크 | 앨범마다 하나. `/invite/<토큰>`. 발급일부터 7일. 화면 문구는 '참여 링크' (지금: `주소?invite=<4자 코드>`) |
| 게스트 | 가입 없이 링크로 들어와 기록을 남기는 사람 |
| 내 앨범 | 홈에 보이는 목록. 내가 만든 앨범과 링크로 합류한 앨범만 |

표기 규칙 (`src/data/photos.ts`, `src/data/album.ts`):

| 자리 | 형식 | 예 |
|---|---|---|
| 사진 날짜 · 시간 | 촬영 시각(`takenAt`)에서 만든다 | `2023년 7월 11일`, `오후 7시 40분` |
| 사진 위 캡션 | 날짜 · 시간 · 장소 | `2023년 7월 11일 · 오후 7시 40분 · 파리` |
| 앨범 기간 | 같은 해면 뒤쪽 연도 생략. 비워 둔 날짜는 사진의 촬영 날짜로 채운다 | `2023년 7월 10일 - 7월 17일` |
| 홈 카드 · 초대 앨범 선택 | 시작일만 | `2023년 7월 10일` |
| 연대표 · 사진 타일 | 짧은 날짜 | `7. 11` |
| 목소리 길이 | 분:초 | `0:37` |
| 앨범 읽기 맺음말 | 읽는 날짜 + 요일 | `2026년 9월 18일 금요일 기록` |

## 3. 전역 상태

저장은 서버가 맡습니다. 답변·음성 파일·STT 결과·AI facts·글·참여자·초대 토큰은 모두 DB와 스토리지에 있고, 화면 상태는 지금 무엇을 보고 있는지에 대한 것만 들고 있습니다.

| 상태 | 값 | 어디에 | 비고 |
|---|---|---|---|
| `screen` | 화면 키 20개 중 하나 | React state (`src/App.tsx`) | 첫 값은 `login` |
| `history` | 거쳐온 화면 스택 | React state | 뒤로가기(`goBack`)가 꺼내 쓴다. 탭↔탭 이동 때 비운다 |
| `albums` | 앨범 목록 | React state | 만들기·정보 수정·링크 재발급이 여기를 고친다 (지금: 시드 5개에서 시작하고 새로고침하면 되돌아간다) |
| `openId` | 지금 열어 둔 앨범 id | React state | 상세·앨범 정보·기록할 사진·기록·목소리·글·사진 추가·알림 클릭·초대 기본 선택이 모두 이 앨범을 본다 |
| 대상 사진 id | 지금 기록 중인 사진 | 앱 상태에 있어야 한다 | 기록·목소리·글 화면이 어느 사진인지 알아야 한다 (지금: 없다. §10) |
| `justCreated` | 앨범을 막 만든 직후인가 | React state | 초대 화면을 '앨범을 만들었어요' 모드로 바꾼다. 초대 화면을 벗어나면 false |
| `invitedId` | 링크로 들어온 앨범 id | React state | 게스트 화면이 이 앨범의 커버·제목·사진을 본다. 없으면 `openId` 앨범 |
| `inviteExpired` | 링크가 만료됐는가 | React state | true면 게스트 랜딩이 만료 안내로 바뀐다 |
| `ready` | 부팅이 끝났는가 | React state | false 동안 부팅 화면 |
| 회원 세션 | 로그인한 계정 | 서버 세션 | (지금: `localStorage.dasiBomAuth` — provider · email · name · tone(캐릭터 0~3) · color(배경색 0~7) · marketing · onboarded · createdAt. 목업 로그인 0.7초) |
| 가입 이력 | 공급자별 계정 1개 | 서버 | (지금: `localStorage.dasiBomAccounts`. 재로그인 때 신규/기존 판단. 탈퇴 때만 지워진다) |
| 게스트 세션 | 참여자 id | **HttpOnly 쿠키** | 서버가 내준다. 화면 코드가 읽지 않는다 (지금: 쿠키 없음. `localStorage.dasiBomGuest`에 닉네임 문자열만) |
| 초대 토큰 | `/invite/<토큰>` 경로의 토큰 | URL 경로 | 부팅 때 경로에서 읽어 서버에 묻는다 (지금: `?invite=<4자 코드>` 쿼리. 첫 로드에 한 번만 읽고, 아는 코드는 시드 5개뿐) |
| 사진 | 앨범 id → 사진(촬영 시각 · 장소 · 목소리 · 글) | 서버 | (지금: 메모리 스토어 `src/data/photos.ts`. 사진 추가로만 늘어난다) |
| 구성원 | 앨범 id → 구성원(회원 + 게스트) | 서버 | (지금: 메모리 스토어 `src/data/family.ts`. 회원의 링크 합류로만 늘어난다) |
| 멤버십 | 앨범 id → 내 역할(owner / member) | 서버 | (지금: 메모리 스토어 `src/data/membership.ts`) |

(지금: `albums`와 메모리 스토어 3개는 새로고침하면 시드로 돌아가고, 남는 것은 localStorage 3키뿐이다. 시드 앨범은 다섯이다 — 2023년 유럽여행(eu23 · EU23 · 내가 만듦 · 발급 2일 전) · 제주 가족여행(jeju · JEJU · 초대받음 · 23일 전 → 이미 만료) · 할머니와 보낸 여름(summer · SUMMER · 내가 만듦 · 1일 전) · 바닷가 산책(seaside · SEA · 아직 내 앨범 아님 · 6일 전) · 첫째 초등학교 1학년(school1 · SCH1 · 내가 만듦 · 3일 전 · 사진 20장).)

## 5. 이동 규칙

뒤로가기는 두 종류입니다.

| 종류 | 화면 | 어디로 |
|---|---|---|
| 방문 기록(`history`)에서 꺼낸다 | `S3E_ALBUM_EDIT`, `S3L_RECORD_LIST`, `S10E_PROFILE_EDIT`, `S7_INVITE`(앨범 상세에서 들어온 경우만) | 실제로 거쳐온 화면. 기록이 비어 있으면 홈 |
| 목적지 고정 | `S2_CREATE`→홈, `S3_DETAIL`→홈, `S4_INTERVIEW`→상세, `S5_VOICE`→기록 남기기, `S6_STORY`→상세, `S8_UPLOAD`→상세, `G2_INFO`→랜딩, `G3_ANSWER`→참여자 정보, `A3_PROFILE`→약관, `A2_TERMS`→로그인(세션 삭제) | 들어온 길과 무관 |

- 탭 홈 4개에는 뒤로가기가 없다. 홈만 상단 바(워드마크 → 홈, 아바타 → 내 정보)가 있고, 나머지 셋은 상단 바 없이 제목이 홈 워드마크와 같은 높이에서 시작한다.
- 탭 홈 사이를 오가면 `history`를 비운다. 홈 `···`→공유도 홈→초대 이동이라 기록이 비고, 초대 화면에 뒤로가기가 붙지 않는다.
- 탭 홈이 아닌 화면으로 가면 지금 화면을 `history`에 쌓는다. 지금 화면과 같은 화면으로는 가지 않는다.
- 앨범 만들기가 끝나면 `history`를 `[home]`으로 갈아끼우고 초대로 간다. 만들기 화면으로는 돌아갈 수 없다.
- 새 앨범 만들기 입구는 홈의 카드와 우측 하단 원형 ＋, 그리고 참여 중인 앨범이 없을 때의 초대 화면 셋이다. 하단 탭에는 없다.
- 앨범 상세로 들어가는 길은 홈 카드(열림 모션), 알림 2건, 회원이 초대 링크를 타고 합류한 직후 셋이다.

### 7.3 S2_CREATE — 새 앨범 만들기 (B-04)

어두운 작업대 안에 표지 미리보기와 그 바로 아래 커버 색 스와치가 있고, 그 아래 밝은 바탕에 `표지 꾸미기`와 `앨범 정보` 두 묶음이 이어집니다. **시작일·종료일 칸은 없습니다** — 기간은 사진의 촬영 날짜에서 채워지고, 직접 적는 일은 앨범 정보 수정(§7.5)에서 합니다.

```
표지 꾸미기 — 대표 사진 · 앨범 판형(세로 4:5 / 정사각 / 가로 4:3) · 사진이 보이는 자리(기본 창 / 레터링 / 정사각 창 / 타원 창 / 사진 표지)
앨범 정보 — 앨범 제목(필수) · 짧은 설명
커버 색 11가지 — 작업대 안 표지 바로 아래. 처음에는 무작위로 하나 골라 둔다
  ├ 제목이 비어 있는가?
  │    ├ Y → [앨범 만들기] 비활성
  │    └ N → 제출 가능
  ├ 대표 사진 파일이 이미지(image/*)인가?
  │    ├ Y → 미리보기 표시. 버튼 문구 "대표 사진 변경"
  │    └ N → 토스트 "이미지 파일만 선택해주세요". 파일 무시
  │    ("JPG, PNG · 최대 10MB"는 안내 문구만. 용량 검사 없음)
  └ 제출 → 버튼 "앨범을 만들고 있어요…"(비활성) → 앨범 생성
        → 초대 토큰 발급, 유효기간 7일   (지금: 4자 코드를 즉석에서 만들고 id = 코드 소문자. 0.5초 지연)
        → 시작일·종료일은 빈 값으로 둔다 (사진이 들어오면 촬영 날짜가 기간이 된다)
        → 대표 사진이 없으면 회색 자리 커버
        → 내 목록 맨 앞에 추가. 역할 owner. openId = 새 앨범
        → history = [home], justCreated = true → S7_INVITE (생성 직후 모드. §7.10 (d))

뒤로가기 → S1_HOME
```

(지금: 새 앨범의 회색 커버는 사진을 올려도 바뀌지 않는다.)

### 7.4 S3_DETAIL — 앨범 상세 (B-06 · B-07 · B-08 · C-06 · C-07 · C-08)

위에서부터 판형 그대로의 hero(기간 · 제목 · 구성원 이름 줄), 상위 탭 앨범 · 기록입니다. **요약 카드는 없습니다** — 사진 수·목소리 수·글 수를 한 줄로 보여주던 카드와 하단에 떠 있던 [＋ 사진 추가]가 모두 상단 바로 올라갔습니다.

상단 바는 사진 위에 흰색으로 얹힙니다. 뒤로가기 + [기록] + [사진 추가] + 케밥입니다.

| 트리거 | 분기 | 결과 |
|---|---|---|
| 뒤로가기 | — | → `S1_HOME` (고정. 거쳐온 화면과 무관) |
| 상단 [기록] | — | → `S3L_RECORD_LIST` (남은 사진이 없으면 그 화면이 "모든 사진의 기록이 끝났어요."를 알린다) |
| 상단 [사진 추가] | — | → `S8_UPLOAD` |
| 케밥 → 구성원 초대 | — | → `S7_INVITE` (앨범 고정. §7.10 (c)) |
| 케밥 → 앨범 수정 | — | → `S3E_ALBUM_EDIT` |
| 구성원 이름 줄 | — | 명단 모달 "기록 중인 사람 n명" (나 포함) |

이름 줄은 겹친 프로필 최대 3개(나 먼저)와 "나 · 엄마 · 아버지 외 n명"입니다. 모달 첫 줄은 나이고, 만든 사람이면 "이 앨범을 만들었어요", 링크로 들어왔으면 "초대 링크로 참여했어요"가 붙습니다. 그 아래 구성원마다 상태 뱃지(참여 중 / 초대됨 / 다시 초대)가 붙고, 모달에서 재초대는 못 합니다. 게스트도 이 명단에 함께 나옵니다. (지금: 게스트는 나오지 않는다.)

상위 탭 '앨범' (읽기):

| 트리거 | 분기 | 결과 |
|---|---|---|
| 사진이 0장 | — | "아직 사진이 없어요. 위 ‘사진 추가’로 시작해보세요." |
| 사진 (즉석사진 프레임) | — | **라이트박스 오버레이**를 연다. 화면 이동이 아니다 |
| 사진마다 | 글이 있는가? | Y → 글 본문 / N → 점선 상자 "그 날의 이야기를 기록해요." + [기록하기] → `S4_INTERVIEW` (그 사진을 지목해서) |
| 목소리 행 ▶ | 재생 중인가? | Y → ■ 아이콘 / N → ▶ 아이콘 (지금: 토스트만 뜨고 소리는 나지 않는다) |

앨범 설명 아래에 사진이 촬영 시각순으로 이어집니다. 사진마다 번호(`01`), "날짜 · 장소", 기울어진 즉석사진 프레임, 제목, 글, 목소리 행 순서입니다. 끝에는 "{오늘 날짜} {요일}요일 기록" 한 줄이 있습니다.

상위 탭 '기록' → 하위 탭 4개:

| 하위 탭 | 트리거 | 분기 | 결과 |
|---|---|---|---|
| 사진 | 상태 칩 | 전체 / 기록 전 / 기록 완료 (개수 표시) | 목록을 걸러낸다. 결과가 없으면 "이 상태의 사진이 없어요." |
| 사진 | 사진 타일 | 기록이 하나라도 있는가? | Y → `S6_STORY` / N → `S4_INTERVIEW` |
| 목소리 | ▶ | 재생 중인가? | 아이콘 토글 (지금: 토스트만. 소리 없음) |
| 목소리 | 연필 아이콘 ({이름}의 목소리 수정) | — | → `S5_VOICE` |
| 글 | 상태 칩 | 전체 / 기록 전 / 기록 완료 | 같은 칩. 위에 "전체 n개" |
| 글 | 카드 버튼 | 글이 있는가? | Y → [글 수정] → `S6_STORY` / N → [기록하기] → `S4_INTERVIEW` |
| 연대표 | 항목 | 기록이 하나라도 있는가? | Y → `S6_STORY` / N → `S4_INTERVIEW` |

사진 타일에는 앨범에서 몇 번째인지(`n번째`)가 왼쪽 위에, 기록 전 사진에만 `기록 전` 뱃지가 오른쪽 위에 붙습니다. 목소리·글·연대표도 같은 번호를 부릅니다. 네 탭 모두 비어 있을 때 안내 문구가 따로 있습니다(사진 "아직 사진이 없어요." · 목소리 "아직 도착한 목소리가 없어요. 가족을 초대해보세요." · 글 "사진을 추가하면 글을 쓸 수 있어요." · 연대표 "사진을 추가하면 시간순으로 정리해드려요.").

(지금: 어느 사진을 눌렀는지 다음 화면에 전달되지 않는다. 상태 판정도 두 갈래다 — 목록·칩은 목소리/글 유무로 보고, 기록·목소리 화면은 저장된 `status` 값을 본다. §10)

```
  — 지금 값이 채워져 있다. 상태 필드 없음. 시작일·종료일은 이 화면에만 있다
  ├ 날짜를 비워 둔 앨범이면 칸에 사진에서 채운 날짜가 연하게 보이고, 아래에 "비워 둔 날짜는 사진의 촬영 날짜로 채워져요. 사진이 늘면 그만큼 기간도 넓어져요."

  └ 제목이 비었거나, 바뀐 값이 하나도 없는가?
      ├ Y → [저장하기] 비활성
      └ N → 앨범 갱신 → 토스트 "앨범 정보를 저장했어요" → 거쳐온 화면
```

### 7.7 S4_INTERVIEW — 사진 기록 남기기 (C-03)

사진 한 장을 지목해서 들어옵니다. 질문은 그 사진의 것이고, **수가 정해져 있지 않습니다.** 사진을 올릴 때 기본 질문이 만들어져 있고, 답을 낼 때마다 AI가 질문을 바꾸거나 꼬리질문을 더할 수 있어 남은 질문이 중간에 늘어날 수 있습니다. 그리고 **모든 질문에 답하지 않아도 글이 만들어집니다** — 중간에 그만둬도 그때까지 제출된 답변이 분석되면 글이 나옵니다.

```
진행 표시 = "남은 질문 {n}개"        (지금: "질문 n / 3" 고정 진행 바)
사진(캡션 날짜 · 시간 · 장소) · 질문 카드 "AI가 사진을 보고 물어봐요"
질문 = 그 사진의 질문 목록에서 다음 하나   (지금: 앨범·사진과 무관한 고정 3문장을 차례로 돌린다)
이전 기록 인용 = 그 사진에 이미 들어온 답에서 뽑는다   (지금: 2·3번째 질문에 같은 문장이 박혀 있다)

  ├ [목소리로 답하기] → S5_VOICE (같은 질문을 들고 간다)
  ├ [글로 답하기] → 글 입력 모드 (최대 500자, "n / 500")
  │    └ 글이 비어 있는가?
  │        ├ Y → 제출 버튼 비활성
  │        └ N → 제출 → 답변 저장(DB)
  │              └ AI가 이 답을 보고 질문을 바꾸거나 꼬리질문을 더했는가?  (미정: 분석이 언제 도는지)
  │                  ├ Y → 남은 질문이 늘어난다 → 다음 질문
  │                  └ N → 다음 질문
  │              └ 남은 질문이 0인가?
  │                  ├ N → 다음 질문으로. 입력을 비우고 선택 모드로 복귀
  │                  └ Y → 제출된 답변 분석 → 글 생성 → S6_STORY
  ├ [이 질문은 건너뛸게요]
  │    └ 남은 질문이 더 있는가?
  │        ├ Y → 다음 질문 (쓰던 글은 그대로)
  │        └ N → 아래 '그만두기'와 같은 갈래로
  └ [나가기] / 뒤로가기 — 중간에 그만두기
       └ 이 사진에 제출된 답변이 하나라도 있는가?
            ├ Y → 제출된 답변 분석 → 글 생성 → S6_STORY   (지금: 없는 경로. 언제나 S3_DETAIL로 나간다)
            └ N → S3_DETAIL

사진이 하나도 없으면 "아직 기록할 사진이 없어요. 사진을 먼저 추가해주세요."만 보인다
```

글이 만들어지면 그 사진은 기록 완료가 되고, 상세의 사진·글·연대표 탭과 기록할 사진 화면의 개수가 함께 바뀝니다. (지금: 답·녹음·글이 어디에도 저장되지 않고 사진 상태도 바뀌지 않는다. 3번째 답을 내면 토스트 "사진 기록이 완성됐어요" 뒤 곧장 글 화면으로 가지만, 그 글은 방금 기록한 사진이 아니라 글이 있는 첫 사진이다.)

### 7.8 S5_VOICE — 목소리로 답하기 (C-04)

대상 사진과 질문은 기록 남기기에서 들고 옵니다.

```
대기 — "버튼을 누르면 실제 녹음이 시작돼요" · "최대 5분까지 녹음할 수 있어요" · [글로 답하기] → S4_INTERVIEW
  [● 마이크] → getUserMedia({audio:true}) + MediaRecorder
    ├ 권한 거부 / 장치 없음 / MediaRecorder 미지원 → 토스트 "마이크 권한을 허용하거나 글로 답해주세요". 대기 유지
    └ 허용 → 녹음 중: 파형 애니메이션 + 타이머 mm:ss + "듣고 있어요. 편하게 이야기해주세요." ([글로 답하기] 숨김. 지금: 5분 자동 정지 없음)
         [■ 정지] → <audio controls> 미리듣기 (실제 재생) · "녹음이 완료됐어요" · "재생해 확인한 뒤 목소리를 남겨주세요"
              ├ [다시 녹음] → 녹음본 폐기. 타이머 00:00. 대기로
              └ [이 목소리 남기기] → 음성 파일 업로드(스토리지) → STT → 답변으로 저장(DB)
                    └ 그 사진에 남은 질문이 있는가?
                        ├ Y → S4_INTERVIEW (다음 질문)
                        └ N → 제출된 답변 분석 → 글 생성 → S6_STORY
                    (지금: 파일은 버려지고 토스트 "목소리를 안전하게 저장했어요" 뒤 곧장 S6_STORY)

뒤로가기 → S4_INTERVIEW. 화면을 벗어나면 마이크 트랙 정리
```

(지금: 질문은 1번 질문 문장이 화면에 박혀 있고, 대상 사진은 저장된 `status`가 '기록 전'인 첫 사진이다.)

### 7.9 S6_STORY — 사진 기록 (글) (C-05 · C-08)

지목해서 들어온 사진의 글을 보여주고, 좌우로 같은 앨범의 다른 글로 넘어갑니다. (지금: 글이 있는 사진이 하나라도 있으면 그 사진들만, 없으면 앨범 사진 전체를 넘겨 본다. 시작은 언제나 첫 사진이다. 사진이 없으면 "아직 기록이 없어요."만 보인다.)

| 모드 | 트리거 | 결과 |
|---|---|---|
| 공통 | 사진 위 ◀ ▶ | 이전 / 다음 사진. 카운터 "n / N", 날짜 · 시간 · 장소 · 제목 · 글 · 목소리 카드가 함께 바뀐다. 양 끝에서는 그쪽 버튼을 숨긴다 |
| 보기 | 상단 [수정] | 수정 모드 |
| 보기 · 수정 | 목소리 카드 | ▶ / ■ 토글. 목소리 없는 사진은 "가족의 목소리 · 아직 목소리가 없어요" (지금: 토스트만. 소리 없음) |
| 수정 | 제목 입력 · 본문 입력 | 고친 값을 저장한다 (지금: 비제어 입력이라 값이 잡히지 않는다) |
| 수정 | 문체 [따뜻하게] [담백하게] [회고록처럼] | 고른 문체로 글을 다시 만든다 (지금: 선택 표시와 저장 토스트 문구만 바뀐다) |
| 수정 | 하단 [기록 저장하기] | 저장 → 보기 모드 복귀 + 토스트 "{문체} 스타일로 기록을 저장했어요" (지금: 아무 데도 반영되지 않는다) |
| 수정 | 상단 [취소] | 보기 모드 |
| 공통 | 뒤로가기 | → `S3_DETAIL` |

(지금: 태그 4개, 인용 카드, 하단의 "이 글은 가족이 남긴 기록을 모아 AI가 정리했어요." 문구는 고정값이다. 태그·인용은 AI facts에서 나와야 한다.)

### 7.10 S7_INVITE — 초대 (D-01 ~ D-06)

들어온 길에 따라 네 가지 모습입니다.

| 진입 경로 | `justCreated` | 앨범 고정(`locked`) | 상단 뒤로가기 | 하단 탭 | 앨범 선택기 | 나가는 길 |
|---|---|---|---|---|---|---|
| (a) 하단 탭 '초대' | false | false | 없음 | 있음 | 앨범 2개 이상이면 드롭다운 | 하단 탭 |
| (b) 홈 `···` → 공유 | false | false | 없음 | 있음 | (a)와 같음. 그 앨범이 미리 선택 | 하단 탭 |
| (c) 상세 케밥 → 구성원 초대 | false | true | 있음 (→ 상세) | 없음. 화면을 꽉 채운다 | 숨김 | 뒤로가기 |
| (d) 앨범 생성 직후 | true | true | 없음 | 없음. 화면을 꽉 채운다 | 숨김 | 우측 상단 ✕ → `S1_HOME` / [앨범에 사진 추가] → `S8_UPLOAD` |

(b)가 (a)와 같은 이유는 홈→초대가 탭 홈 사이의 이동이라 `history`가 비고, 뒤로가기는 `history`가 있을 때만 붙기 때문입니다(`src/App.tsx`). 기본 선택 앨범은 `openId`(마지막으로 열어 둔 앨범)입니다. 앨범 선택기는 세로 리스트가 아니라 **드롭다운**입니다 — 고른 앨범 한 줄(커버 · 제목 · 시작일 · 사진 n장)만 보이고, 누르면 목록이 펼쳐지며 고른 줄에 체크가 붙습니다.

제목은 (d)에서 "앨범을 만들었어요" + "이제 함께 기록할 가족을 초대해보세요. 링크를 받은 가족은 가입 없이 참여할 수 있어요." + 방금 만든 앨범 한 줄(커버 · 제목 · 기간)입니다. 탭으로 들어오면 "초대", 앨범에서 들어오면 상단 바가 "초대"이고 제목이 "우리의 추억을 기록해요"입니다. 둘 다 아래에 "앨범 구성원은 누구나 새 구성원을 초대할 수 있어요."가 붙습니다.

```
참여 중인 앨범이 하나도 없는가?
  ├ Y → 제목 "초대하기"(탭) / "우리의 추억을 기록해요"(앨범에서) + "아직 참여 중인 앨범이 없어요. 앨범을 만들면 가족에게 참여 링크를 보낼 수 있어요."
  │     + [새 앨범 만들기] → S2_CREATE
  └ N → 링크 카드 "‘{앨범}’ 참여 링크"   링크 = {origin}/invite/{토큰}   (지금: {origin}{pathname}?invite={4자 코드})
        └ 링크가 만료됐는가? (발급 + 7일 ≤ 지금)
            ├ N → 라벨 오른쪽에 "D-{n}" (n=0이면 "D-DAY") + ⓘ. ⓘ를 누르면 말풍선 "초대 링크 유효기간은 일주일이에요. {월 일}까지 쓸 수 있고, 만료되면 새로 만들 수 있어요." + 닫기
            │     ├ [복사] → 클립보드 API. 실패하면 textarea + execCommand('copy') → 토스트 "참여 링크를 복사했어요"
            │     └ [공유하기] → navigator.share 가 있는가?
            │            ├ Y → OS 공유 시트 (제목 "{앨범}에 초대해요"). 취소하면 아무 일 없음
            │            └ N → [복사]와 같은 동작
            └ Y → 뱃지 "만료됨". 링크 취소선. [복사] 비활성. "{만료일}에 만료됐어요. 링크를 새로 만들면 다시 초대할 수 있어요."
                  └ [링크 새로 만들기] ([공유하기] 자리) → 토큰·발급 시각 교체. 구성원은 그대로
                        → 토스트 "새 참여 링크를 만들었어요. 7일간 쓸 수 있어요" → 카드가 유효 상태로
                        (미정: 새로 만들면 옛 토큰이 바로 막히는지)

(d)에만: [앨범에 사진 추가] → S8_UPLOAD

기록 중인 사람 {n}명  (지금: 나는 빼고 센다 — 상세 모달과 숫자가 다르다. §10)
  ├ 구성원 없음 → "아직 초대한 가족이 없어요."
  ├ 참여 중 / 초대됨 → 상태 뱃지 (지금: "기록 n개" 같은 부속 문구는 시드 고정값)
  └ 다시 초대 → [다시 초대] 버튼 → 초대 재발송 → 그 줄이 '초대됨'으로 바뀌고 문구가 "초대를 다시 보냈어요"로
                → 토스트 "{이름}에게 초대를 다시 보냈어요"
```

(지금: 새로 발급한 토큰과 새 앨범의 토큰은 새로고침 뒤 부팅 분기에서 인식되지 않는다. §6은 시드 상수만 본다.)

### 7.11 S8_UPLOAD — 사진 추가하기 (C-01)

한 앨범에 담을 수 있는 사진은 20장입니다. 이 상한을 실제로 막는 곳은 이 화면 하나입니다.

```
[내 컴퓨터에서 사진 고르기]  (터치 기기는 "폰에 저장된 사진 불러오기")
  └ 데스크톱 크로미움(File System Access API)인가?

  └ 남은 자리(20 − 앨범의 사진 − 이미 고른 사진)가 0인가?
```

## 8. 게스트 플로우 (D-08 · D-09)

게스트는 가입하지 않지만 **DB의 참여자**입니다. 참여자 정보를 내는 순간 서버가 참여자로 저장하고 HttpOnly 세션 쿠키를 내주며, 그 뒤 남기는 답변·음성·글은 회원의 기록과 같은 자리에 쌓입니다. 그래서 게스트도 앨범 구성원 명단에 나타나고, 답은 목소리로도 낼 수 있습니다.

### 8.1 G1_WELCOME — 초대 랜딩

```
링크가 만료됐는가? (inviteExpired)
  ├ Y → "링크가 만료됐어요" + "참여 링크는 만든 날부터 7일 동안만 쓸 수 있어요. 초대한 가족에게 새 링크를 부탁해주세요."
  │     └ [닫기] → 주소에서 토큰 제거 → S1_HOME  (미정: 비회원이 갈 곳. 지금은 회원 홈으로 간다. §10)
  └ N → 앨범 커버 (캡션 "{초대한 사람}님이 초대했어요") · "가족 앨범 초대" · 앨범 제목
        · 참여 3단계 안내 ("사진을 천천히 살펴봐요" / "AI 질문에 목소리나 글로 답해요" / "가족의 한 편의 기록으로 완성돼요")
        ├ [이 앨범에 참여하기] → G2_INFO
```

(지금: 캡션의 "하연님이 초대했어요"는 고정 문구다.)

### 8.3 G3_ANSWER — 기록 남기기

```

  ├ [목소리로 답하기] → 녹음 → 음성 파일 업로드 → STT → 답변 저장(DB)   (지금: 없는 경로. 화면에 글 입력만 있다)
  ├ 글 입력 (최대 500자)
  │    └ 비어 있는가?
  │        ├ Y → 제출 버튼 비활성
  │        └ N → 제출 → 답변 저장(DB) ([기록 저장하고 다음 사진]. 마지막 사진은 [기록 모두 제출하기])
```

## 10. 미구현 / 알아둘 것

기준 코드 `dd8647e`에서 확인한 것만 적었습니다. 플로우를 그리는 사람이 화면을 열어 보고 "문서가 틀렸다"고 생각하지 않도록, 지금 화면이 문서와 갈라지는 자리를 전부 모았습니다. 서버 연동 전에 손봐야 할 목록은 [개발현황](./개발현황.md)에 있습니다.

**저장되지 않는 것**

- 기록 답변·녹음 파일·글 수정은 어디에도 저장되지 않는다. 토스트만 뜬다. 새로고침하면 사진·구성원·앨범까지 모두 시드로 돌아간다.
- 글 화면의 제목·본문 입력은 비제어(`defaultValue`)라 고친 값이 잡히지도 않는다. 문체 버튼은 저장 토스트의 문구만 바꾼다.
- 게스트의 관계·동의는 버려지고 닉네임만 `localStorage.dasiBomGuest`에 남는다. HttpOnly 세션 쿠키가 아니다.
- 사진을 UI로 '기록 완료'로 만드는 경로가 없다. 사진 상태를 바꾸는 코드 자체가 없다.
- 사진 추가는 메모리 스토어에만 들어가고, 사진마다 질문을 만들지 않는다.

**두 갈래로 갈라진 것**

- 사진 상태 판정이 둘이다. `photoStatus()`는 목소리나 글이 하나라도 있으면 기록 완료로 보고(`src/data/photos.ts:33-36`), 상세의 탭·칩·타일과 기록할 사진 화면이 이걸 쓴다. 반면 `interview.tsx:34`와 `voice.tsx:23`은 저장된 `photo.status` 값을 읽는다. 시드 데이터에 둘이 어긋나는 사진이 있어(예: eu23 '다 함께한 저녁 식사' — `status: 기록 전`인데 목소리가 있다) 사진 탭에서는 기록 완료로 보이는 사진이 기록 화면에서는 대상이 된다.
- 글 탭도 한 카드 안에서 갈라진다. 칩은 `photoStatus()`로 거르고 버튼은 `photo.story` 유무로 갈리므로, 목소리만 있고 글이 없는 사진은 '기록 완료'로 걸러지면서 본문은 "아직 글이 없어요"이고 버튼은 [기록하기]다.
- 구성원 수가 화면마다 다르다. 초대 화면은 나를 빼고 세고(`participants.length`), 상세 명단 모달은 나를 더해 세고(이름이 같은 사람은 한 번만), 홈 카드는 나 + 구성원을 얼굴 3개 + `+n`으로 보여준다. 시드 앨범처럼 명단에 내 이름이 없으면 상세가 초대보다 1 크다.

**연결되지 않은 것**

- 어느 사진을 눌렀는지 다음 화면에 전달되지 않는다. 앱 상태에 앨범 id만 있고 사진 id가 없다. 기록 남기기·목소리는 `status`가 '기록 전'인 첫 사진을, 글은 글이 있는 첫 사진을 연다. 상세의 사진·글·연대표에서 어느 타일을 눌러도 결과가 같다.
- 질문은 사진과 무관하다. 회원은 `interview.tsx:14-18`의 3문장, 게스트는 `guest.tsx:191-195`의 3문장을 돌려 쓴다. 2·3번째 질문에 붙는 '이전 기록' 인용도 고정 문장이다.
- 알림은 2건 고정이고 하단 탭 배지도 2 고정이다. 읽음 처리가 없고, 두 건 모두 문구에 적힌 앨범이 아니라 마지막으로 연 앨범으로 간다.
- 게스트 완료 화면의 "사진 3장", "3장 / 2개", 초대 랜딩의 "하연님이 초대했어요", 글 화면의 태그 4개·인용 카드, 구성원 줄의 "기록 n개"는 모두 고정값이다.
- 앨범 삭제는 만든 사람에게만 메뉴가 보이고, 눌러도 토스트만 뜬다.

**부팅·링크**

- 초대 링크는 경로가 아니라 쿼리스트링(`?invite=<4자 코드>`)이고, 첫 로드에 한 번만 읽는다. 아는 코드는 시드 상수 다섯 개(EU23 · JEJU · SUMMER · SEA · SCH1)뿐이라 **초대 화면에서 새로 발급한 코드도, 새로 만든 앨범의 코드도 새로고침 뒤 인식되지 않는다.** 링크 재발급과 앨범 만들기를 화면에서 확인할 수는 있어도 그 링크를 타고 들어올 수는 없다.
- 게스트 흐름을 마치거나 만료 안내를 닫으면 세션 없이 홈에 도달한다. 비회원인데도 시드 '내 앨범' 4개가 그대로 보인다.
- 로그인은 목업이다. 실패 경로가 없고, 구글과 카카오는 별개 계정이다.

**그 밖에**

- 사진 상한 20장(`MAX_PHOTOS`, `album-cover.tsx:14`)을 실제로 막는 곳은 사진 추가 화면(`upload.tsx:52`) 하나다. 시드 앨범 school1은 정확히 20장이다.
- 목소리 재생은 아이콘 토글 + 토스트다. 소리가 나는 곳은 녹음 직후 미리듣기 하나다. 녹음은 5분 안내만 있고 자동 정지가 없다.
- 새 앨범의 회색 커버는 사진을 올려도 바뀌지 않는다. 촬영 시각·장소는 EXIF에서 읽고, 없는 사진만 파일 수정 시각과 "위치 없음"으로 간다.
- 홈의 정렬 드롭다운은 목록 앞뒤만 뒤집는다. 데이터에 수정 시각이 없다.
- 내 정보의 알림 스위치는 화면을 벗어나면 켜짐으로 돌아간다.
- 건너뛰기(기록 남기기·게스트)는 쓰던 글을 지우지 않는다.
